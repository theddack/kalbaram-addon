## 0. 먼저 — 이번에 하지 않은 것

- 특정 아이템을 몇 위로 보내려고 계수를 만지지 않았다. 바꾼 것은 ① 치명타 가중치가 **어느 지표 칸**으로 가는지, ② 반대 유형 차단을 **무엇을 근거로** 푸는지 둘뿐이다.
- 가중치 수치(`concept.aug`, `LIFT_FROM_CALC`, `flips` 임계값 0.5 …)는 하나도 바꾸지 않았다.
- B1·B2 밖의 계산 구조(정규화·목적 함수·증강 점수·수치 계산식)는 건드리지 않았다.

## 1. B1 — 스킬 치명타와 평타 치명타를 지표 칸에서 나눔

### 무엇이 틀렸나

`skillCritDmg`·`effectCritDmg`·`ultCritDmg`(스킬·아이템 효과에 치명타가 붙는 증강)가 평타 치명타와 같은 `CRIT` 태그로 묶여, `metricWeights` 가 그 가중치를 통째로 평타 칸(`dps`)에 넣었다. 수치 계산(`Stats.evaluate`)은 같은 효과를 이미 콤보 쪽에 반영하고 있어서 **같은 효과를 두 번 센 셈**이었다.

### 어떻게 고쳤나

| 자리 | 바꾼 것 |
|---|---|
| `scaleTags` | 스킬 치명타 키와 '평타로 발동하지 않는 치명타 효과'에 `CRITSKILL` 표식을 더한다. 아이템 태그가 아니라서 아이템 점수에는 쓰이지 않는다 |
| `conceptWeights` | 증강이 올린 치명타 중 스킬 몫만 `CRITSKILL` 로 넘긴다 (`min(lift.CRITSKILL, lift.CRIT)`). 챔피언 본래 치명타 성향은 그대로 평타 칸에 남는다 |
| `metricWeights` | `combo += 스킬 몫`, `dps += 치명타 가중치 − 스킬 몫` |

치명타 아이템을 원하는 근거(`lift.CRIT`)는 그대로 둬서 **연계는 끊기지 않는다**.

### 수정 전후

| 챔피언 + 증강 | dps 가중치 | combo 가중치 |
|---|---|---|
| 아리 + 보석 건틀릿 | 0.018 → **0.379** (21.5배) ⇒ **0.099** (5.6배) | 0.692 → **0.520** ⇒ **0.800** |
| 아리 + 보석 팔찌 | ⇒ 0.011 (0.6배) | ⇒ 0.816 |
| 아리 + 취약 | ⇒ 0.138 | ⇒ 0.722 |
| 징크스 + 보석 건틀릿 | ⇒ 0.339 (평타 몫 남음) | 0.302 ⇒ 0.601 |
| 아리·징크스 + 치명적인 공격(순수 치명타 확률) | **변화 없음** | 변화 없음 |

징크스는 본래 치명타 성향이 평타 칸에 그대로 남고 증강이 올린 몫만 스킬 칸으로 간다 — **스킬·평타 치명타가 동시에 유효한 경우 양쪽이 다 남는다.**

## 2. B2 — 반대 유형 차단을 증강 근거별·아이템 능력치별로 나눔

### 무엇이 틀렸나

증강이 올린 반대 유형 태그가 0.5 만 넘으면 반대 유형 아이템 **전체**가 한 번에 열렸다.

- `전술적 대비`(사망 시 보호막 = 주문력 300%): 주문력이 **보호막 계수에만** 쓰이는데 징크스의 차단 29개 → 0개
- `3연발`·`주문 분산`·`다중 공격`: 주문력 계수가 **하나도 없는 설명 태그**(AP 0.5) 하나로 물리 챔피언 78명 전원의 차단이 꺼짐

### 어떻게 고쳤나

1. **근거를 좁혔다** — 반대 유형을 여는 건 그 능력치가 증강의 **피해 계산**에 실제로 쓰일 때만. `scaleTags(dmgOnly)` 로 회복·보호막 계수를 빼고, 증강별 `_dmg` 를 `augContext` 가 같이 넘긴다. 규칙이 `lift` 를 직접 정한 증강은 그 태그를 근거로 본다.
2. **열 때도 능력치별로** — 전체가 아니라 그 능력치를 가진 아이템만 연다.
3. **요구 아이템은 따로 통과** — 고른 증강이 이름으로 요구·연계하는 아이템(`무한의 대검 업그레이드`·`궁극의 히드라` …)은 반대 유형이어도 막지 않는다. 예전엔 그 증강의 태그가 전체를 열어 줘서 같이 통과했는데, 이제 그 아이템만 통과한다.
4. **유형 환산 증강은 그대로 전체 해제** — `적응형 능력치`·`마법사` 2종. 비정석 빌드를 막지 않는다.

### 수정 전후

| 사례 | 차단된 전설 아이템 |
|---|---|
| 징크스 (증강 없음) | 29 |
| 징크스 + 전술적 대비 | 0 ⇒ **29** |
| 징크스 + 3연발 / 주문 분산 / 다중 공격 | 0 ⇒ **29** |
| 징크스 + 적응형 능력치 (유형 환산) | 0 ⇒ **0** (그대로) |
| 아리 (증강 없음) | 46 |
| 아리 + 보석 건틀릿 | 0 ⇒ **31** (치명타를 가진 15개만 열림) |
| 아리 + 무한의 대검 업그레이드 | 0 ⇒ **45** (요구 아이템 1개만 열림) |

아리 + 보석 건틀릿에서 **무한의 대검·정수 약탈자는 치명타 연계로 통과**하고(공격력이 같이 붙어 있다는 이유로 막지 않는다), **치명타가 없는 몰락한 왕의 검·요우무·세릴다는 계속 차단**된다. 순위 자체는 계산에 맡겼다 — 무한의 대검은 28위다.

## 4. 향후 개선 목록 — '불필요'와 '범위 밖'을 갈랐다

지적대로 수치 계산이 **필요 없는** 효과와 **지금 엔진이 표현하지 못하는** 효과를 나눴다. `tools/aug_weight_audit.js` 의 분류에 갈래를 하나 더 만들어 `docs/증강_가중치_연결표.md` §4 를 다시 생성했다 (예전 36개 → 21 + 15).

| 갈래 | 수 | 뜻 |
|---|---:|---|
| 직접 수치 계산 불필요 (§4.3) | 21 | 값이 다른 경로로 이미 계산에 들어가거나(아이템·증강 지급·업그레이드) 추천에 쓸 전투 수치가 아님(소환사 주문·골드·이동 수단) — **더 할 일 없음** |

| 어느 스킬인지 챔피언 데이터에 없음 | 메아리 시전 | 스킬 분류 데이터가 더 필요 |
| 챔피언 대상이 아님 | 소환술사 | 미니언은 계산 대상이 아니다 |

### Phase 2 에서 새로 확인한 범위 밖 항목

- **스킬 치명타가 '어느 스킬'에 붙는지 구분하지 못한다.** 이번 수정은 증강별로 스킬 몫과 평타 몫을 가르지만, 챔피언 쪽은 스킬/평타를 한 덩어리로만 본다. 징크스 Q 처럼 **평타를 강화하는 스킬**은 스킬 치명타의 덕을 거의 못 보는데 계산은 그걸 모른다 (징크스 + 보석 건틀릿의 combo 0.302 → 0.601 은 이 한계 안에서 나온 값이다). → 모형을 넓힐 항목, 가중치로 때우지 않는다.
- **`CRITSKILL` 의 세기는 `LIFT_FROM_CALC`(0.6)를 그대로 쓴다.** 스킬 치명타 증강마다 적용 범위(스킬 전부 / 아이템·지속 피해만 / 궁극기만)가 다른데 세기는 같다. 원본에 적용 범위별 값이 따로 없어 지금은 구분하지 않는다 — 구분하려면 가정값 승인이 필요하다.

## 5. 아직 확인하지 못한 것

1. **실제 게임 확인 0건.** 위 숫자는 전부 계산끼리의 비교다.
2. **`flips` 임계값 0.5 는 그대로다.** 계획대로 임계값 자체는 승인 전까지 건드리지 않았다. 이번 수정은 '얼마나 커야 여는가'가 아니라 '무엇을 근거로 여는가'만 바꿨다.
3. **물리 챔피언의 부분 해제는 효과가 없다.** 반대 유형 아이템 29개가 사실상 전부 주문력 아이템이라, 열리면 다 열린다. 마법 챔피언에서만 좁혀진다.
4. **징크스 + 스킬 치명타의 combo 상승폭**이 타당한지는 위 4장의 한계 때문에 확인할 수 없다.
5. **Top3 가 바뀐 10장면 중 2건(케일)** 은 화면에서 본 적 없는 조합이다 — 기록은 있으나 그 시점의 실제 선택과 대조하지 않았다.
