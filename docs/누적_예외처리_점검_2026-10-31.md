# 누적 예외 처리 점검 (2026-10-31, v0.1.77 기준)

버그를 고치면서 쌓인 조건문·예외 처리가 서로 부딪히거나 정상 동작을 막는지 점검했다.

- 원칙: 실행 경로를 따라 재현한 것만 고쳤다. 재현 테스트가 수정 전 코드에서 실패하는 것을 먼저 확인했다.
- 판단 근거: 재현 조건이 실제로 생길 수 있는지는 기록 18판(`events.json`)과 대조해 판단했다.
- **실게임 검증 필요**: 아래 수정은 모두 실제 게임에서 확인하지 않았다.

## 재현됐지만 고치지 않은 것 (조건이 실제 기록에 없음 · 설계 결정 필요)

- **다음 선택 화면에 지난 화면 이름이 섞이는 경우**: 고른 것을 잃고(`not any(a in _last)`), 빈칸이 같이 있으면 툴팁 규칙에 걸려 새 화면을 무시한다. 하지만 기록 48번의 화면 전환 중 지난 이름이 다시 나온 적은 0번이었고, 이 조건은 툴팁 오인식을 막고 있다.
- **놓친 클릭 + 다음 화면 첫 읽기에 빈칸이 있을 때 '새로고침 씀'이 다음 화면으로 이어짐**: 판정 문턱을 바꾸면 빠른 연속 새로고침에서 표시를 잃을 위험이 있어 두었다.
- **선택 화면이 떠 있는 중에 새 게임 처리(`Tracker.new_game`)**: 카드 상태와 클릭이 남거나 사라진다. 기록에서는 늘 새 게임 처리가 선택 화면보다 먼저였다.
- **판 도중 챔피언 값이 잠깐 비면 새 게임으로 처리**: 게임 구분 키가 `(champion, gameMode)`뿐이다. 기록의 unknown 판은 판 도중 갈라진 게 아니라 처음부터 챔피언이 빈 별개 기록이었다.
- **새 판 시작 직후 끝난 증강 칸·점수판 작업**: 횟수(`_hud_runs`, `board_reads`)가 새 판에 1씩 더해진다. 판 사이 간격이 길어 실제로는 거의 생기지 않는다.
- **넓혀 찾기**: 정한 칸이 없으면 클릭 짐작이 맞아도 끝나지 않는다. 진행 중 다음 고르기를 이전 결과로 붙일 수도 있다. 기록에서 넓혀 찾기가 성공한 적이 한 번도 없다.
- **증강 칸 칸 순서**: 같은 줄의 칸 순서가 실수 좌표 차이로 뒤바뀔 수 있다. 화면은 순서를 쓰지 않는다.
- **증강 칸이 안 보인다는 판정(`hud_blind`)**: 상점·죽음으로 가려진 회차도 세어, 한 번 걸리면 그 판 끝까지 확인을 안 한다. 테스트가 이 동작을 의도로 고정하고 있어 결정이 필요하다.

## 재현 안 된 의심

- 선택 화면을 닫는 바로 그 읽기 중에 누른 클릭이 버려질 수 있다 (스레드 타이밍).
- 새로고침 연출이 2.5초보다 길면 옛 이름이 다시 받아들여질 수 있다.
- `_verified` 가 판이 바뀌어도 안 비워진다.
- 증강 칸 후보 자리 5개(`max_cands`)가 칸이 4개 찼을 때 모자랄 수 있다 (2520x1575에서 3·4번째를 못 찾는 것의 후보).
- 자동 보호(protect)가 점수판 읽기도 끈다 (설명에는 없음).

## 기존 기능에 미치는 영향

- 증강 인식은 빈칸·새로고침이 섞인 경우의 판정만 바뀐다. 우르곳·바드·하이머딩거 판 기존 테스트는 그대로 통과한다.
- 추천 점수·가중치·등급은 바뀌지 않는다. 바뀌는 것은 '강한 선택'·'새로고침 권장'·'변신' 표시와 '지금 살 것' 부품 후보뿐이다. 추천 기준선 테스트(`baseline.test.js`)도 통과한다.
