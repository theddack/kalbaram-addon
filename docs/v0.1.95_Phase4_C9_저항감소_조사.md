# C9 — 저항 감소 공통 계산 규칙 조사·구현 계획

v0.1.95 Phase 4 · 2026-11-25 · 코드 기준 `web/stats.js` · 데이터 기준 `web/data.json`(패치 16.20) · `rules.json`

> **조사와 구현 계획까지만**이다. 이 문서에는 코드 변경이 없다.
> 아이템 이름마다 예외를 두지 않고, **같은 효과를 다시 쓸 수 있는 계산 규칙**을 먼저 찾는 것이 목표다.

## 0. 지금 코드가 하는 일 (사실 확인)

```js
// web/stats.js:445
function mitigation(resist, pctPen, flatPen) {
  const eff = Math.max(0, resist * (1 - pctPen) - flatPen);
  return 100 / (100 + eff);
}
// web/stats.js:607-608
const physMit = mitigation(TARGET.ARMOR, t.ARPEN, t.LETHALITY) * …
const magMit  = mitigation(TARGET.MR * (1 - Math.min(0.9, cv.mrShred || 0)), t.MPENP, t.MPEN) * …
```

| 항목 | 지금 상태 |
|---|---|
| 비율 **마법 저항력** 감소 | `cv.mrShred` 하나뿐. 쓰는 데이터는 **핏빛 저주 1개**(0.1125) |
| 비율 **방어력** 감소 | **계산 키가 아예 없다** (`armorShred` 를 읽는 코드가 없음) → 칠흑의 양날 도끼 6%×5중첩 미계산 |
| 고정 저항 감소 | **키 없음** → 악의 마법 저항력 −10 미계산 |
| 여러 출처 합치기 | `conv[k] += v` 로 **더한다** (게임은 비율끼리 곱한다) |
| 음수 저항 | `Math.max(0, …)` 로 자른다 (게임은 음수까지 내려가며 피해가 더 들어간다) |
| 저항 감소로 **아군**이 더 넣는 피해 | 통로 없음 (`out.allyDmg` 는 아군 강화 효과만 받는다) |

## 1. 적용 순서 (원본 확인)

위키 기준 순서는 **① 고정 감소 → ② 비율 감소 → ③ 비율 관통 → ④ 고정 관통(치명)** 이다
([Armor penetration](https://wiki.leagueoflegends.com/en-us/Armor_penetration) ·
[Magic penetration](https://wiki.leagueoflegends.com/en-us/Magic_penetration) · [Armor](https://wiki.leagueoflegends.com/en-us/Armor)).
고정 감소는 추가 저항부터 깎고 그다음 기본 저항을 깎는다. 비율 **관통**은 저항이 0 이하면 아무 일도 안 한다.
저항 **감소**는 0 아래로 내릴 수 있지만, 이 순서 때문에 실제로 음수가 되는 일은 거의 없다고 위키 자신이 적고 있다.

→ 지금 코드의 `mitigation(MR × (1 − mrShred), MPENP, MPEN)` 은 ②③④ 순서로는 **맞다**. 빠진 것은 ① 하나다.
→ 그러므로 공통 규칙은 `mitigation(resist, pctPen, flatPen, pctRed, flatRed)` 한 군데만 늘리면 된다.

```
eff = max(0, ((R − flatRed) × (1 − pctRed)) × (1 − pctPen) − flatPen)
```

## 2. 발동 조건·지속시간·중첩 (원본 설명 그대로)

| 아이템/증강 | 원본 효과 | 발동 조건 | 지속 | 중첩 | 지금 |
|---|---|---|---|---|---|
| **칠흑의 양날 도끼** (깎아내기) | 대상 **방어력 6% 감소** | 챔피언에게 **물리 피해**를 입히면 | **6초** | **5회 (최대 30%)** | 미계산 |
| 칠흑의 양날 도끼 (열정) | 이동 속도 +20 | 물리 피해를 입히면 | **2초** | 없음 | `MS 15` (가동률 75% 가정) |
| **악의** (증오안개) | 지면 장판 + **마법 저항력 10 감소**(고정) | **궁극기로 챔피언에게 피해** | **3초** | 없음 | 장판 피해만 계산 (`effects`), 감소는 미계산 |
| **핏빛 저주** (썩은 부식) | 마법 저항력 **7.5% 감소** | **스킬·기본 지속 효과의 마법 피해** | 6초 | 4회 (최대 30%) | `mrShred 0.1125` (중첩 평균 1.5 가정) |
| **부식** (증강) | 방어력·마법 저항력 **1.5% 감소** | 적에게 피해를 입히면 | 4초 | **20회 (최대 30%)** | `ARPEN·MPENP 15%` — **관통 자리에 잘못 들어가 있다** |
| **나서스 E 영혼의 불길** | 대상 **방어력 30~50% 감소** | 스킬 적중 | 약 5초(+1초) | 없음 | 미계산 (아래 4절) |

**사용자가 지적한 두 가지를 확인했다.**

- **칠흑의 이동 속도 가동률 75% 를 방어력 감소에 그대로 쓰면 안 된다.** 둘은 **서로 다른 패시브**다.
  이동 속도(열정)는 **2초·중첩 없음**이라 "계속 때리면 거의 켜져 있다"가 성립하지만,
  방어력 감소(깎아내기)는 **6초·5중첩**이라 *켜짐/꺼짐*이 아니라 **몇 중첩이 쌓여 있나**의 문제다.
  → 가동률이 아니라 **중첩 평균**으로 재야 한다 (핏빛 저주와 같은 방식).
- **악의의 고정 마법 저항력 감소는 상시가 아니다.** 조건이 **궁극기 적중**이고 지속이 **3초**다.
  → `ultUptime(3)` = `min(1, 3 / 궁극기 재사용 대기시간)` 꼴로 재야 한다. 이 헬퍼는 `stats.js:631` 에 이미 있다
  (존야·궁 발동 효과가 쓰는 것과 같은 자리).

### 중첩 도달 속도 — 계산 규칙 제안

중첩형은 모두 같은 꼴이다: **한타 동안 쌓는 속도 × 지속시간 → 평균 중첩**.

```
쌓는 횟수/초  r = (평타 r_auto = 공격 속도) 또는 (스킬 r_skill = 콤보 스킬 수 ÷ 콤보 시간)  ← 조건(on)에 따라 고름
포화 중첩     s* = min(최대 중첩, r × 지속)
평균 중첩     s̄ = s* × (1 − 포화까지 걸린 시간 ÷ 한타 시간)  … 램프 구간 보정 (한타 AUTO_FIGHT_SEC = 6초)
값           = 중첩당 값 × s̄
```

이 식 하나로 칠흑(물리 피해 → 평타+스킬, 6초, 5중첩), 핏빛 저주(스킬 마법 피해, 6초, 4중첩),
부식(모든 피해, 4초, 20중첩)이 **같은 규칙**으로 풀린다. 지금 세 개가 각각 다른 가정값
(75% 가동률 / 중첩 평균 1.5 / 평균 10중첩)으로 손으로 적혀 있는 것을 이 규칙으로 대체한다.

> 램프 보정 항은 **가정**이다 (근거 자료 없음). 지금 쓰고 있는 세 가지 가정값도 전부 `noData: true` 라,
> 가정을 없애는 게 아니라 **가정을 한 군데로 모으는** 변경이다.

## 3. 동일 효과의 중복 적용

- **같은 아이템 두 개**: 데이터의 `limit` 필드가 막는다 (칠흑 `"Fatality"`, 핏빛 저주 `"Blight"`). 이미 있는 장치다.
- **다른 출처끼리**: 게임에서는 **비율 감소끼리 곱해서** 쌓인다 (30% + 30% = 51%, 60% 아님).
  지금 `conv.mrShred` 는 **더한다**. 출처가 핏빛 저주 하나뿐이라 지금은 틀린 값이 나오지 않지만,
  칠흑·부식·나서스를 같이 넣으면 그 순간부터 과대평가가 된다.
  → 공통 규칙에서 `PCT_PEN` 과 같은 방식(`1 − (1−a)(1−b)`)으로 합쳐야 한다. 고정 감소는 더한다.
- **감소와 관통**: 서로 다른 단계라 둘 다 적용된다 (1절 순서).

## 4. 챔피언 스킬의 저항 감소 — 지금은 조사 경로가 없다

`web/data.json` 의 챔피언 스킬에는 **설명 문장이 들어 있지 않다** (`spells[].desc` 가 전부 `null`).
그래서 "스킬로 저항을 깎는 챔피언이 몇 명인가"를 지금 데이터로는 셀 수 없다.
처음에 자동 검색으로 "0명"이 나왔는데 그건 **효과가 없다는 뜻이 아니라 원본 문장이 없다는 뜻**이다 — 정정한다.

실제로 나서스 E(영혼의 불길)는 **대상 방어력 30~50% 감소**가 맞다
([Nasus](https://wiki.leagueoflegends.com/en-us/Nasus) · [Data Nasus/Spirit Fire](https://wiki.leagueoflegends.com/en-us/Template:Data_Nasus/Spirit_Fire),
다만 위키 본문 쪽이 오래되어 해당 패치 값은 따로 확인이 필요하다).
아이템만 고치고 챔피언 쪽을 비워 두면 "칠흑은 세는데 나서스 E 는 안 센다"가 되므로,
**공통 규칙의 키는 챔피언 스킬에서도 쓸 수 있는 이름**으로 둔다 (`champions` 규칙에서 같은 키를 읽게).
챔피언 스킬 원본 문장을 넣는 일 자체는 **C7·Phase 5A 와 같은 '원본 데이터 경로' 문제**라 그쪽에 묶는다.

## 5. 저항 감소로 아군이 더 넣는 피해

관통은 **나만** 득을 보고, 저항 감소는 **그 대상을 때리는 모두**가 득을 본다. 이게 둘의 진짜 차이다.
지금 모델에는 이 통로가 없다. 다만 **새 모델이 필요하지는 않다** — 기준 아군 `ALLY`(`stats.js:460`)가 이미 있고
`allyGain()` 이 '아군이 더 넣는 피해'를 체력 단위로 바꾸는 자리도 있다.

```
allyShredGain = (ALLY.autoDps + ALLY.skillDps) × (감소 후 피해배율 ÷ 감소 전 피해배율 − 1) × 지속 몫 × 아군 수
```

- 아군 수는 지금의 **1명** 규칙을 그대로 쓴다 (회복·보호막·아군 강화와 같은 기준, `ALLY_TARGETS`).
- 이건 C8(받는 피해 분포)이나 C4(아군 회복)와 **다른 종류의 확장이 아니다**. 기존 ALLY 모델로 바로 된다.
- 그래도 **C9 본체와는 분리**한다. 저항 감소를 내 피해에 반영하는 것(C9-A)과
  아군 몫까지 더하는 것(C9-B)은 영향 범위가 다르고, C9-B 는 지원 지표 쪽 가중치를 건드린다.

## 6. 구현 계획 (승인 전, 코드 변경 없음)

| 단계 | 내용 | 영향 | 승인 필요 |
|---|---|---|---|
| **C9-A1** | `mitigation()` 에 `pctRed`·`flatRed` 인자 추가 (1절 순서). 기본값 0 → **기존 결과 불변** | 없음 (항등) | 아니오 |
| **C9-A2** | 합치기 규칙: 비율 감소는 곱(`PCT_SHRED`), 고정 감소는 합(`FLAT_SHRED`). `mrShred` 는 이름을 그대로 두고 비율 집합에 넣는다 | 핏빛 저주 단독이면 불변 | 아니오 |
| **C9-A3** | 중첩·조건 공통 함수 `shredExpect({perStack, stacks, dur, on})` (2절 식) | 핏빛 저주 값이 0.1125 → 식 값으로 바뀐다 | **예** |
| **C9-A4** | 데이터 연결: 칠흑(방어력 6%×5·6초·물리), 악의(고정 10·3초·궁), 부식(1.5%×20·4초)을 공통 키로 | 세 효과가 새로 계산된다 | **예** |
| **C9-A5** | 부식을 `ARPEN·MPENP` 에서 빼낸다 (관통 자리에서 감소 자리로) | 증강 가중치에 영향 | **예** |
| **C9-B** | 아군 몫(5절) | 지원 지표에 영향 | **예**, 별도 항목 |

**검증 계획**: ① `mitigation` 순서 단위 테스트(고정→비율→비율관통→고정관통) ② 기준선 263장면 불변 확인(A1·A2 뒤)
③ 전 챔피언 173명에서 '상대 방어력이 높을수록 칠흑 점수가 오르는가' 단조성 ④ 실게임 85장면 수정 전후 비교
⑤ 중첩 식이 바꾸는 핏빛 저주 값의 변화량을 따로 적는다.

**순서 제안**: A1·A2 는 결과가 안 바뀌므로 먼저 넣어 두고, A3~A5 는 한 번에 묶어 승인받는다.
A3 를 먼저 혼자 넣으면 핏빛 저주만 값이 움직여 비교가 지저분해진다.
