## 0. 먼저 — 기획서의 전제 세 가지가 사실과 달랐어요

기획서는 오류를 4건으로 보고 원인을 네 가지로 나눠 두셨는데, 원본 이벤트를 열어 보니 달랐어요.

| 2.2 케이틀린 = **OCR 후보 매칭 오류** | **OCR 은 세 칸을 다 맞게 읽었어요.** 클릭을 고르는 규칙 문제예요 | 431.6초 읽은 선택지 `['빙글빙글','아티스트 보호','순수주의자 - 마법사']` — 정답 '아티스트 보호'가 그대로 읽혔어요 |

| 2.4 파이크 = **추측 클릭이 확실 클릭보다 먼저 기록됨** | 순서는 맞지만 **지금 코드는 순서를 아예 안 봐요.** 확실·짐작을 따로 모아 두고 확실을 먼저 써요 | `augocr.py` `Tracker.click` / `_chosen` |

**그래서 실제 결함은 4건이 아니라 2종류예요.**

| 결함 | 판 | 추천 영향 |

| **B. 새로고침한 칸의 새 이름을 읽기 전에 그 칸을 누르면 이름 없이 기록된다** | 그레이브즈 | 빌드 방향이 통째로 달라졌어요 |

미스 포츈은 결함이 아니고, 케이틀린은 A 와 같은 결함이에요.

## 1. 결함 A — 클릭 우선순위

### 지금 코드

`augocr.py` 의 클릭 처리는 두 곳이에요.

```python
# _click_at(): 이미 뗀 클릭은 '직전 확인 때 위치'를 확실한 클릭으로, '지금 위치'는 짐작으로
px, py = hit[2], hit[3]          # 직전 위치
slot = card_at(pos, px, py)      # → 확실 (sure)
if slot is None and rr is None:
    guess = card_at(pos, rx, ry) # 지금 위치 → 짐작 (guess)

# Tracker.click(): 확실·짐작을 따로 처음 것만 담는다
if sure and self._click is None:   self._click = slot
elif not sure and self._guess is None: self._guess = slot

# Tracker._chosen(): 확실이 있으면 확실
return self._click if self._click is not None else self._guess
```

**시간 순서를 보지 않아요.** 짐작이 먼저 와도, 뒤에 확실이 오면 확실이 이겨요.

### 파이크 (2026-11-16, 253초)

```
253.0 선택지 ['속전속결', '바다의 영혼', '그림자 질주']
253.0 click x=0.287 y=0.472  slot=None guess=0  tap=[0.325, 0.78]
253.6 click x=0.412 y=0.399  slot=1
254.2 click x=0.694 y=0.393  slot=2
254.4 click x=0.694 y=0.393  slot=2
255.2 PICKED '바다의 영혼'  (경기 결과 정답: 속전속결 = 0번 칸)
```

- 253.0 의 **직전 위치 (0.325, 0.78)** 는 카드도 새로고침 버튼도 아니에요
  (새로고침 띠는 y 0.66~0.76, 카드 몸통은 y 0.18~0.66). 그래서 확실한 칸이 안 나왔어요.
- **지금 위치 (0.287, 0.472)** 는 0번 카드 위 → 짐작 0. **이게 정답이었어요.**
- 0.6초 뒤 253.6 의 클릭이 1번 칸으로 잡혀 **확실**이 되고 짐작을 이겼어요.
- 254.2·254.4 에 같은 자리를 두 번 누른 건 카드가 닫힌 뒤 게임 화면을 누른 모양이에요
  (같은 판 578초에도 똑같은 모양이 나와요).

### 케이틀린 (2026-11-16, 431초)

```
431.6 선택지 ['빙글빙글', '아티스트 보호', '순수주의자 - 마법사']
431.6 click x=0.5  y=0.296  slot=None guess=1  tap=[0.687, 0.789]
433.5 click x=0.72 y=0.213  slot=2
433.8 PICKED '순수주의자 - 마법사'  (경기 결과 정답: 아티스트 보호 = 1번 칸)
```

같은 모양이에요. 직전 위치 (0.687, 0.789) 는 카드 밖 → 짐작 1(정답), 1.9초 뒤 2번 칸 클릭이 이겼어요.
**OCR 은 세 이름을 다 맞게 읽었어요.** 후보 매칭 문제가 아니에요.

### 왜 이렇게 돼 있나 — 뜻이 중간에 뒤집혔어요

| 시기 | '짐작'의 뜻 | 우선순위 |
|---|---|---|
| 2026-10-28 (`1e3bc27`) | **직전 위치** (지금 위치가 카드 밖일 때) | 확실(지금 위치) 먼저 — 합리적 |
| 2026-11-08 이후 (지금) | **지금 위치** (직전 위치가 카드 밖일 때) | 확실(직전 위치) 먼저 — 그대로 남음 |

11월에 '직전 위치가 더 믿을 만하다'로 바꾸면서 확실·짐작의 의미가 **서로 바뀌었는데,
우선순위 규칙은 10월 그대로 남았어요.** 그래서 지금은 '덜 믿을 만한 쪽을 먼저 쓰는' 모양이 됐어요.

`tests/test_python.py` 의 `test_guessed_click_is_used_only_without_sure_click` 두 번째 단언이
그때 규칙을 그대로 담고 있어요. 이 단언은 **실제 사고 기록이 아니라 그때의 설계 의도**예요.

### 대안 비교 (아직 적용 안 함)

`tools/aug_replay.py --rule` 로 7판을 그대로 다시 돌려 비교했어요.

| 규칙 | 뜻 | 7판 결과 |
|---|---|---|
| `now` (지금) | 확실이 있으면 확실, 없으면 짐작 | **맞음 3** · 칸 모자람 1 · 다름 3 |
| `first` | 확실·짐작 가리지 않고 **먼저 온 클릭** | **맞음 5** · 칸 모자람 1 · 다름 1 |

`first` 는 파이크·케이틀린을 고치고, **이미 맞던 3판(바드·베인·그레이브즈 233645)은 그대로예요.**

근거도 맞아요 — 카드는 누르는 순간 골라지니까(`Tracker.click` 주석) **첫 클릭이 고른 카드**고,
그 뒤 클릭은 사라지는 카드 위나 게임 화면을 누른 거예요. 지금 코드는 이 원칙을
'확실끼리', '짐작끼리' 따로만 지키고 있어요.

**주의할 점:** `first` 는 위 테스트의 두 번째 단언과 부딪혀요. 고치려면 그 테스트를
'먼저 온 클릭' 기준으로 다시 쓰면서, **왜 바뀌는지(11월에 뜻이 뒤집힌 것)를 같이 적어야 해요.**
테스트를 통과시키려고 지우는 게 아니라, 규칙이 바뀌었다는 걸 남기는 거예요.

## 2. 결함 B — 새로고침한 칸을 이름 읽기 전에 누름

### 그레이브즈 (2026-11-15 23:53, 17~22초)

```
17.4 선택지 ['탭 댄서', '최종 형태', 'RISE']
19.1 click reroll=0          ← 0번 칸 새로고침 → 그 칸 이름을 비움
20.3 drawn 카드              ← 화면은 다시 그렸지만
20.7 click slot=0            ← 1.6초 만에 새 카드(검을 뽑아라)를 누름
21.0 click slot=None
21.9 PICKED None  from=[None, '최종 형태', 'RISE']
48.8 verify click=None result='증강 칸에서 못 찾음'
```

- 새로고침과 클릭 사이에 **`offers` 가 한 번도 없어요.** 새 이름을 읽을 틈이 없었어요.
- 누른 칸이 0번이라는 건 알지만 **그 칸 이름을 모르니 `None` 으로 기록**돼요.
- 증강 칸(게임 HUD)으로도 못 건졌어요. 이 판은 끝까지 게임 증강 칸이
  `['우르프의 챔피언','고반동','가라앉은 자의 축복']` 3개만 보였고 검을 뽑아라는 한 번도 안 보였어요.
  (같은 판 551.2초 '고반동' 확인이 *공용 아이콘이라 확인 안 함* 으로 끝난 걸 보면,
  아이콘이 겹치는 증강은 칸에서 가려내지 못해요.)

### 지금 구조에서 가능한 것 / 안 되는 것

| 방법 | 가능? | 이유 |
|---|---|---|
| 그 자리에서 이름 다시 읽기 | **이미 하고 있어요** | 새로고침 때 `_reread_n = _frag_n = 0` 으로 다시 읽기를 허용해요. 1.6초 안엔 못 끝났어요 |
| 증강 칸(HUD)으로 메우기 | **이 판은 안 돼요** | 검을 뽑아라가 칸에서 한 번도 안 보였어요 (아이콘 겹침 추정) |
| 경기 결과로 메우기 | 사후에만 | 판이 끝난 뒤라 그 판 추천에는 못 써요 |
| **미확정으로 남기고 알리기** | **됩니다** | 누른 칸(0번)과 '이름 모름'을 같이 들고 있을 수 있어요 |

### 대안 비교 (아직 적용 안 함)

| 대안 | 내용 | 평가 |
|---|---|---|
| A. 새로고침 직후 클릭이면 잠깐 기다렸다 읽기 | 클릭을 보류하고 N초 더 읽어 본다 | **기다리는 시간이 지어낸 값**이에요. 화면이 이미 닫혀서 읽을 게 없을 수도 있어요 |
| B. 새로고침 전 옛 이름으로 메우기 | `_reroll_old` 의 이름을 쓴다 | **반대.** 2026-10-20 신드라 판에서 이것 때문에 한 판 내내 틀렸고, 그래서 지금 비우게 돼 있어요 |
| C. **미확정으로 남긴다** | 칸 번호만 들고 'UNKNOWN' 으로, 증강 칸이 보이면 그때 메운다 | 지어낸 값이 없어요. 기획서 §6 '증강 1개 확인 필요' 표시와 맞아요 |
| D. 사용자가 직접 고르게 | 화면에서 손으로 지정 | C 와 같이 가면 자연스러워요. 기획서도 필수가 아니라고 했어요 |

**추천: C(+ D 설계만).** 지금은 `picked: None` 이 그냥 묻히고 사용자도 몰라요.
적어도 **모른다는 걸 알리는 것**이 지금보다 나아요.

## 3. 미스 포츈 — 결함이 아니에요

```
   0.0 게임 증강 칸 ['Twinfire']            ← 지난 판 값이 남아 있던 것
  11.1 게임 증강 칸 ['ARAM_Erosion']        ← 스스로 바로잡음 (기록 시작 전에 고른 '부식')
  23.6 + TakeemDownDownDown (전부 다 무너뜨려)
  33.1 + GoH_PentakillAug_Q (헤비)
1068.1 + GoH_PentakillAug_E (스래시)        ← 게임이 실제로 더해 줬어요
```

- 1056.8초 선택 화면 `['파워','스래시','둠']` 은 **진짜 선택 화면**이에요 (죽어 있는 동안 떴어요).
- 경기 결과는 `playerAugment1~6` **6칸뿐**이고(`lcu.py`), 이 판은 그보다 많이 골랐어요.
  `gamelog.py` 의 `shortfall`(칸 모자람) 주석에 **이 판이 이미 사례로 적혀 있어요**:
  "표시용 칸(펜타킬 3176)이 한 칸을 써서 실제로 고른 증강 하나가 결과에 안 남았다 → 감지 실패가 아니다".
- 저장된 `eog` 에 `shortfall` 표시가 없는 건, 그때 `slots`(채워진 칸 수)를 같이 안 넘겼기 때문이에요.

**→ 고칠 것은 인식이 아니라 '정답과 맞추는 쪽'이에요.** 칸이 꽉 찬 판은 '다름'으로 세지 말고
'칸 모자람'으로 나눠야 해요. 재생 도구(`tools/aug_replay.py`)에는 이미 그렇게 넣었어요.

### 같이 확인된 것 — 자동 정정은 살아 있어요

11.1초의 `Twinfire → ARAM_Erosion` 이 `Overlay._settle_unverified` 가 실제로 동작한 기록이에요.
**이 장치는 건드리지 않아요.** 남은 실패는 대부분 증강 칸이 안 보이는 동안 일어났어요
(파이크·케이틀린 둘 다 `verify ... '증강 칸이 안 보여 확인 안 함'`).

## 4. 정답(경기 결과)을 얼마나 믿을 수 있나

기획서 §7 은 경기 결과를 정답으로 삼는데, 한계가 있어요.

| 한계 | 내용 |
|---|---|
| 칸 6개 | `playerAugment1~6` 뿐이에요. 더 고르면 안 남아요 (미스 포츈) |
| 표시용 칸 | 펜타킬 묶음 같은 표시용 증강이 칸 하나를 써요 |
| 순서 없음 | 고른 순서가 아니에요 (`gamelog.tidy` 주석) |

그래서 재생 도구는 **맞음 / 칸 모자람? / 다름 / 확인 불가** 로 나눠요.
'칸 모자람?' 은 기록에만 있는 게 있고 결과에만 있는 게 없을 때예요.

## 6. 수정 설계 (Phase 2 에서 할 일)

### 6-1. 클릭 우선순위 — 먼저 온 클릭

- `Tracker.click` 을 '이번 선택 화면에서 **처음 온 클릭**' 하나만 담도록 바꿔요.
  확실·짐작 구분은 **기록에는 남기되**(어떤 근거였는지 알아야 하니까) 고르는 데는 순서를 먼저 봐요.
- `tests/test_python.py::test_guessed_click_is_used_only_without_sure_click` 를 다시 써요.
  없애는 게 아니라 **바뀐 규칙과 그 까닭(11월에 뜻이 뒤집힌 것)을 담아서**요.
- 파이크·케이틀린 재현 테스트를 각각 한 개씩 더해요.

### 6-2. 이름을 못 읽은 선택 — 미확정

- 누른 칸은 알고 이름만 모르는 경우를 `picked: None` 으로 묻지 말고 **'미확정'으로 들고 있어요.**
- 증강 칸이 보이면 그때 메워요 (지금 `_settle_unverified` 길을 그대로 써요).
- 화면에는 '증강 1개 확인 필요'만 조용히 알려요 (게임 화면을 더 가리지 않아요).
- **추천에는 넣지 않아요.** 지금도 `None` 은 안 들어가니 추천 결과는 그대로예요.

### 6-3. 정답 대조 — 칸 모자람 분리

- 재생 도구에서 '칸 모자람'을 '다름'과 나눠 세요 (이미 넣었어요).
- 판 기록을 정리할 때 `slots` 를 같이 넘겨 `shortfall` 표시가 남게 할지 확인해요.

### 안 할 것 (기획서 §11 과 같음)

- OCR 유사도 임계값(`MIN_RATIO`) 은 **건드리지 않아요.** 이번 4판 중 후보 매칭이 원인인 건 **없어요.**
- 목적함수·가중치·정규화 대안 B 는 그대로예요.
- 상태 모델(UNKNOWN/CANDIDATE/CONFIRMED/CORRECTED)을 새로 만들지는 않아요.
  지금 구조(`_click`/`_guess`/`_unverified`/`_settle_unverified`)가 이미 같은 일을 하고 있어서,
  이름만 바꾸는 큰 공사보다 **6-1·6-2 두 가지를 먼저 고치는 게 위험이 작아요.**
  그래도 필요하다고 보시면 Phase 2 에서 같이 하겠습니다.

## 7. 아직 확인 못 한 것

- 그레이브즈 판에서 **검을 뽑아라가 증강 칸에 왜 한 번도 안 보였는지** — 아이콘 겹침으로 짐작만 했어요.
- `_click_at` 의 '직전 위치가 더 믿을 만하다' 가정이 **일반적으로 맞는지** — 7판으로는 모자라요.
  이번 수정은 그 가정을 바꾸지 않고, **순서만** 보도록 하는 거예요.
- 미스 포츈 판에서 게임 증강 칸이 4개에서 멈춘 것 (`MAX_AUGMENTS = 4`) 이
  5개 넘게 고르는 판에서 문제를 일으키는지 — 이번 분석 범위 밖이에요.
