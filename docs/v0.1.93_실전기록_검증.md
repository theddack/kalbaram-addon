# v0.1.93 실전 기록 검증 (3판) — 추천 계산 정확도와 수집 정확도

브랜치 `feat/v0193-ally-support` · 기준: P4-A 적용(`b2a3b2b`) · 자료: 2026-11-15 애드온 0.1.92로 기록한 3판(바드·미스 포츈·베인) · 도구: `node tools/game_log_audit.js`

**이 3판은 오류를 찾는 표본이에요. 추천이 좋다/나쁘다를 통계로 보여 주는 자료가 아니에요.** 비교는 '모델 계산값'과 '게임이 알려 준 값'(Live Client Data) 사이의 비교예요.

**개인정보:** 소환사 이름·PUUID·채팅 토큰은 읽지도 적지도 않았어요. 경기 결과 파일에서는 챔피언 번호·경기 길이·증강 번호만 봤어요. 원본 기록은 저장소에 넣지 않았어요. 테스트 픽스처는 사람이 만든 가짜 기록이에요.

**용어 바로잡기:** 기록의 `rows`는 **[모델 계산값, 게임 실제값]** 순서예요. 1차 분석에서 바드 주문력을 "실제 585 / 모델 639.6"이라고 적었는데, 반대예요. **모델 585 · 게임 639.6**이에요.

- **(새) 누적형 증강의 중첩 (#4):** 극악무도처럼 '영구적으로 쌓이는' 증강은 지금 평균값 하나로 보고 있어요. 실제로는 판마다 크게 달라요(바드 판 후반 +54 주문력). 게임 중 추천에 바로 영향을 줘요.

## D. 자동 검증 도구

`tools/game_log_audit.js` (새로 만듦)

```
node tools/game_log_audit.js <기록 폴더|data 폴더> [--eog <measure 폴더>] [--md 보고서.md] [--json 결과.json]
```

- 폴더를 훑어 `events.json`이 있는 판만 모아요. 같은 판의 zip과 폴더가 같이 있어도 **한 번만** 세요.
- 타임라인을 만들어요: 시작 → 선택지 읽음 → 증강 고름/바로잡음 → 아이템·골드 → 능력치 대조 → 경기 결과.
- **지금 엔진(v0.1.93)으로 다시 계산해요.** 화면과 같은 입력을 써요(즉시 골드 환산 제외, 가동률 조건 능력치 제외, 모루 능력치 포함). 기록 당시 계산값(0.1.92)과 따로 적어 섞이지 않게 해요.
- 증강: 클릭 기록·바로잡음·경기 결과 이름·경기 결과 번호를 대조해요. 모르는 번호를 따로 알려 줘요. 경기 결과 파일은 **챔피언 번호와 증강 번호만** 읽어요.
- 결과를 JSON·Markdown으로 내요.

**테스트:** `tests/log_audit.test.js` 4개 통과. 픽스처(`tests/data/log_audit/`)는 가짜 기록이고, 주문력 한 줄만 일부러 어긋나게 넣어 탐지를 확인해요.

**한계:**
- 기록에 가방 속 부품이 없어 초반 재계산이 낮게 나와요(#6).
- 처치 관여로 쌓이는 능력치가 기록에 없어 그만큼 빠져요.
- 잠깐 켜지는 효과는 구분하지 못해요. 사람이 '같은 값이 계속 어긋나는지'로 판단해야 해요.
- v0.1.92 당시의 **추천 결과 자체**는 다시 만들 수 없어요(그때 아이템 순위를 기록하지 않아요). 능력치만 다시 계산해요.

## E. 다음 작업 제안

**바로 고칠 수 있는 명확한 문제 (추천 계산은 안 건드림)**
1. 경기 결과 칸 부족을 '다름'과 나누기 (#1). 재현 테스트부터.
2. 모르는 증강 번호(3176) 경고·보완 (#2).

**P4-B에 넣을 후보 (실전 근거 있음, 승인 필요)**

4. 성장 조건 아이템(윤 탈) 처리 (#5).

**추가 기록이 필요한 문제**
5. 기록 전에 고른 증강(#3): 게임 시작 직후 증강 칸을 한 번 읽어 두면 짐작을 줄일 수 있어요. 어떻게 할지는 수집 쪽 작업이에요.

**다음 버전으로**
7. 상자가 늦게 사라지는 문제(#9)와 선택 화면 카드 평가 누락은 수집·화면 작업이라 추천 엔진과 분리해서 다뤄요.
