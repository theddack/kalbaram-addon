# v0.1.94 Phase 3 — '증강 4개' 제한 원인 조사 (수정 전 보고)

> 브랜치 `fix/v0194-aug-ocr` · **코드는 안 고쳤어요.** 조사와 수정안만이에요.
> 기록과 코드에서 확인한 것만 적고, 짐작은 짐작이라고 적었어요.

## 0. 결론 먼저

**게임 HUD 문제도 아니고, 아이콘 찾기 문제도 아니에요. `web/app.js` 가 지우고 있었어요.**

`MAX_AUGMENTS = 4`(augocr.py)는 범인이 아니에요. 증강 칸을 **주기적으로 다시 읽을 간격**에만 쓰여요.

진짜 원인은 화면 쪽 한 줄이에요.

```js
// web/app.js applyAug() — 선택 화면이 새로 떴을 때
if (state.chosen.length >= 4 && !extra) {
  const keep = [...state.chosen];
  for (let i = keep.length - 1; i >= 0 && keep.length >= 4; i--) if (!sure.has(keep[i].id)) keep.splice(i, 1);
  state.chosen = keep.slice(0, 3);     // ← 무조건 3개로 자른다
}
```

선택 화면이 뜰 때 고른 증강이 4개 이상이면 **'아직 4개를 다 고르지 않았을 것'이라고 보고**
증강 칸으로 확인 안 된 것을 지운 뒤 **3개로 잘라요.**

## 1. '게임 HUD 가 4개만 보여 주나?' — 아니에요

| 확인한 곳 | 결과 |
|---|---|
| `hudicons.HudReader.scan` | `self.picked` 에 **계속 더하기만 해요.** 개수 상한이 없어요 |
| `hudicons.REGION` | 찾는 범위가 게임 창의 (0.12, 0.70)~(0.75, 1.0) — 칸 수와 무관해요 |
| `augocr.resolve_groups` / `_apply_hud` | 4개 상한이 **없어요** |
| `augocr._slot_ids` | 칸 자리 → 증강 id. 자리 수 제한이 **없어요** |
| `augocr.MAX_AUGMENTS = 4` | `_hud_every()` 한 곳에서만 써요 — 주기 읽기 간격. `if soon or self._verify or self._recover: return 2` 가 **먼저** 걸려서 고른 직후 확인·넓혀 찾기는 영향을 안 받아요 |

`hudicons.scan` 주석에 "칸 순서: 위 줄 왼쪽부터 (2x2 칸)"이 있지만, 이건 **정렬 기준**이지 개수 제한이 아니에요.
게임 화면이 실제로 몇 칸인지는 이 기록으로는 알 수 없어요 (**확인 못 함**).

## 2. 진짜 원인 — 화면이 4번째부터 지워요

### 기록이 보여 주는 것 (미스 포츈 판)

`statcheck.augs` 는 **화면이 들고 있는 고른 증강**(`state.chosen`)이에요.

```
   11.1 [부식]                                  ← 증강 칸으로 바로잡음
   23.6 [부식, 전부 다 무너뜨려]
   33.1 [부식, 전부 다 무너뜨려, 헤비]
  405.1 PICKED 조준경 부착 · verify '증강 칸이 안 보여 확인 안 함'
  405.1 [부식, 전부 다 무너뜨려, 헤비, 조준경 부착]      ← 4개
  550.3 [부식, 전부 다 무너뜨려, 헤비]                  ← 지워짐 (다음 선택 화면)
  568.0 PICKED 과충전 · verify '공용 아이콘이라 확인 안 함'
  568.1 [부식, 전부 다 무너뜨려, 헤비, 과충전]
  842.4 [부식, 전부 다 무너뜨려, 헤비]                  ← 지워짐
  860.1 PICKED 환영 무기 · verify '증강 칸이 안 보여 확인 안 함'
  860.2 [부식, 전부 다 무너뜨려, 헤비, 환영 무기]
 1057.9 [부식, 전부 다 무너뜨려, 헤비]                  ← 지워짐
 1068.0 PICKED 스래시 (판 끝까지 남음)
```

**매번 똑같은 3개로 돌아가요.** 그 3개는 증강 칸(HUD)으로 확인된 것들이에요.
4번째부터는 전부 `증강 칸이 안 보여 확인 안 함` / `공용 아이콘이라 확인 안 함` 이라
'확인됨' 표시를 못 받았고, 그래서 다음 선택 화면마다 지워졌어요.

그레이브즈(23:36) 판도 같아요 — 764.1초에 '불을 밝혀'가 지워졌어요.

### 화면 테스트로 재현했어요

증강 칸이 3개만 보이는 상태를 그대로 만들면:

```
증강 칸 3개 뒤 : 부식 · 전부 다 무너뜨려 · 헤비 · 빈 칸
4번째 클릭 뒤  : 부식 · 전부 다 무너뜨려 · 헤비 · 조준경 부착
다음 선택 화면 뒤: 부식 · 전부 다 무너뜨려 · 헤비 · 빈 칸      ← 지워짐
```

**두 번째 결함도 같은 줄에 있어요.** 앞쪽에 확인 안 된 증강이 끼어 있으면,
**증강 칸으로 확인된 증강까지** `slice(0, 3)` 에 잘려요.

```
확인된 4개 + 짐작 1개: 부식 · 전부 다 무너뜨려 · 헤비 · 조준경 부착(짐작) · 과충전(확인됨)
다음 선택 화면 뒤   : 부식 · 전부 다 무너뜨려 · 헤비 · 빈 칸      ← 과충전도 사라짐
```

(재현 스크립트는 임시 폴더에 뒀어요. 수정할 때 테스트로 옮기면 돼요.)

## 3. 왜 이렇게 됐나 — 두 커밋 사이에 전제가 어긋났어요

| 날짜 | 커밋 | 내용 |
|---|---|---|
| 2026-10-15 | `54dfd0f` | 케일 판: **틀린 클릭 짐작이 4칸을 채워 다음 선택 화면이 막혔다** → 가드 추가 (확인 안 된 것 빼고 3개로 자르기). **그때 `AUG_MAX` 는 4였어요** |
| 2026-10-21 | `3d06504` | 헤드라이너(K/DA)로 증강을 더 받을 수 있게 되자 **`AUG_MAX` 를 6으로** 올리고 `extra` 예외 추가 |

`extra` 예외는 이렇게 생겼어요.

```js
const extra = state.chosen.length >= 4 && state.chosen.slice(0, 4).every((a) => sure.has(a.id));
```

**앞 4개가 모두 증강 칸으로 확인돼야** 예외가 돼요. 그런데 증강 칸은 안 보이는 판이 흔해요
(7판 중 4판에서 `증강 칸이 안 보여 확인 안 함`). 그런 판에서는 예외가 **절대 성립하지 않고**,
10월 15일의 '3개로 자르기'가 그대로 돌아요.

즉 **가드가 막으려던 문제(4칸이 차서 다음 화면이 막힘)는 `AUG_MAX` 를 6으로 올린 10월 21일에 이미 풀렸는데,
가드는 남아 있어요.** 지금 `state.offers` 를 채우는 조건도 `state.chosen.length < AUG_MAX`(6) 이에요.

## 4. 자동 정정에 미치는 영향

| 영향 | 내용 | 근거 |
|---|---|---|
| **자동 정정 자체는 멀쩡해요** | `_settle_unverified`·`_verify` 는 파이썬 쪽에서 `hud_ids`·`_picked_names` 로 돌아요. 화면이 지우는 것과 무관해요 | 미스 포츈 11.1초에 `쌍둥이 불꽃 → 부식` 으로 실제로 고쳤어요 |
| **고쳐 줄 기회가 줄어요** | 화면이 지운 증강은 `state.chosen` 에 없으니, 나중에 증강 칸이 그걸 확인해도 '바로잡기'가 아니라 '새로 더하기'로 들어와요 | `add = hud.filter(...)` 경로. 미스 포츈은 증강 칸이 끝까지 못 봐서 안 돌아왔어요 |
| **추천이 적은 증강으로 돌아가요** | 지워진 뒤로는 3개만 쓰여요. 미스 포츈은 판의 절반 이상을 **고른 6개 중 3개**로 추천했어요 | 550초~판 끝 |
| **확인이 헛돌아요** | 맞게 고른 증강인데 칸에서 못 찾으면 `_unverified` 로 넘어가 넓혀 찾기까지 돌아요 (CPU) | 53.0초 `증강 칸에서 못 찾음` |
| **잘못 바로잡을 가능성** | 구조상 있어요. 다만 **7판에서 한 번도 안 일어났어요** | `_settle_unverified` 조건: 같은 선택지 중 다른 하나가 칸에 새로 나타날 때 |

**즉 '4개 제한'은 자동 정정을 망가뜨리지는 않지만, 자동 정정이 못 미치는 판에서
맞게 고른 증강을 계속 지워요.**

## 5. 최소 수정안 (아직 안 했어요)

### M1 — 확인된 증강까지 자르는 것부터 (작고 분명해요)

```js
state.chosen = keep.slice(0, 3);   →   state.chosen = keep;
```

`keep` 은 이미 '확인 안 된 것을 뒤에서부터 4개 미만이 될 때까지' 뺀 결과예요.
거기에 `slice(0, 3)` 을 또 걸어서 **증강 칸으로 확인된 증강까지** 잘려요 (2절 두 번째 재현).
전제를 안 바꾸고 고칠 수 있어요.

### M2 — 가드 자체 (결정이 필요해요)

| 안 | 내용 | 평가 |
|---|---|---|
| **M2-a. 가드를 없앤다** | `if (state.chosen.length >= 4 && !extra) {...}` 블록 삭제 | 가드가 막던 문제는 `AUG_MAX = 6` 으로 이미 풀렸어요(3절). 틀린 짐작은 파이썬 쪽 `_settle_unverified` 가 바로잡아요. **가장 간단하고, 미스 포츈 유형을 고쳐요.** 증강 칸을 못 읽는 판에서는 틀린 짐작이 남을 수 있는데, **맞는 걸 매번 지우는 지금보다는 나아요** |
| M2-b. `extra` 조건을 넓힌다 | '앞 4개가 모두 확인됨' → '확인을 끝낸(확인됨 또는 확인 불가로 종료된) 것은 건드리지 않음' | 파이썬 쪽 확인 결과를 화면으로 넘겨야 해요 (새 정보 통로). M2-a 보다 큼 |
| M2-c. 그대로 둔다 | M1 만 | 미스 포츈 유형이 남아요 |

**추천: M1 + M2-a.** 둘 다 '지우지 않는다' 쪽이라 **지어낸 값이 없어요.**
되돌리기도 쉬워요 (블록 하나).

### M3 — 곁다리 (같이 보면 좋아요)

`renderOffers()` 의 `const full = state.chosen.length >= 4;` 가 4개부터 증강 이름 직접 입력을 막아요.
`AUG_MAX = 6` 과 어긋나요. 5·6번째를 손으로 고칠 수 없어요.

## 6. 안 한 것 / 모르는 것

- **코드 수정 안 했어요.** 상한을 늘리거나 OCR 주기를 높이지도 않았어요.
- `MAX_AUGMENTS = 4` 도 그대로예요 — 이번 문제의 원인이 아니었어요.
  (다만 4개를 찾으면 주기 읽기가 멈추는 건 사실이라, 나중에 따로 볼 만해요)
- **게임 증강 칸이 실제로 몇 개까지 보여 주는지는 모릅니다.** 기록에 남은 그림으로 세 보면 알 수 있는데,
  이번 조사에서는 코드와 이벤트만 봤어요.
- 미스 포츈 판에서 증강 칸이 조준경 부착·과충전·환영 무기를 왜 못 봤는지 — `증강 칸이 안 보여 확인 안 함`
  (그 판 화면에서 칸을 못 찾음)과 `공용 아이콘이라 확인 안 함` 두 가지 이유가 기록에 있어요.
- 표본은 여전히 7판이에요.
