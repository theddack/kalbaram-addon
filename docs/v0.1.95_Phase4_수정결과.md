## 0. 아직 확인 못 한 것 · 안 한 것 (먼저)

- **실제 게임에서 확인한 것은 하나도 없다.** 아래 숫자는 전부 보유한 기록 5판을 다시 흘려 계산한 값과
  데이터·계산끼리의 대조다. 실제로 플레이해 눈으로 본 것은 0건이다.
- **회복량 추정이 '맞는 값'인지는 여전히 모른다.** 이번에 가른 것은 '무엇을 세고 있는가'(회복 ↔ 보호막)뿐이다.
  한타 한 번에 적이 실제로 회복하는 양이 추정값과 맞는지는 측정한 적이 없다 (보류 항목).
- **아군이 주는 회복은 아직 안 센다** (C4). 보유 5판에 아군 회복 챔피언이 없어 그 차이는 이 기록으로는 못 잰다.
- **원형질 안전벨트의 자기 회복(규칙 `selfHeal` 700)은 여전히 회복량 추정에서 빠져 있다** — 아래 4.2 참고.
  원본 설명에 수치가 없어(`체력을 0 회복`) 회복분과 최대 체력 증가분을 가를 근거가 없다. 손대지 않고 보류로 남겼다.
- **main 병합·태그·PR·릴리스 없음.**

## 1. 고친 것 (커밋 2개)

| 커밋 | 내용 | 건드린 파일 |
|---|---|---|
| C1 | 아이템 효과의 자기 회복과 자기 보호막을 따로 세고, 상대 회복량 추정에서 보호막을 뺀다 | `web/stats.js` `web/app.js` + 테스트 |
| C2 | 상대 추가 체력(`BONUS_HP`)을 실제 상대에서 받아오고, 캐시 열쇠·완충 밴드·복원 경로에 넣는다 | `web/app.js` `web/scoring.js` `web/stats.js`(주석) + 테스트 |

**가중치·목적 함수·증강 계산은 한 줄도 바꾸지 않았다.** 둘 다 '이미 있는 계산이 상대 값을 제대로 받게' 하는 연결 수정이다.

### C1 — 보호막 분리

- `metrics()` 가 `itemSelfHeal` 과 `itemSelfShield` 를 따로 낸다. `itemSelfHp` 는 **둘의 합 그대로** 남겨
  버티는 힘(EHP) 계산(`extraHp`)은 예전과 같은 값을 쓴다.
- `enemyTarget()` 의 회복량이 `selfHeal + vampHeal + itemSelfHeal` 이 됐다 (`itemSelfHp` → `itemSelfHeal`).
  같은 계산을 쓰던 '상대 챔피언 직접 고르기' 경로도 같은 함수(`selfHealOf`)를 쓰도록 하나로 모았다 (두 곳이 어긋나지 않게).

### C2 — 추가 체력 연결

- `enemyTarget()` 이 적 5명의 **추가 체력 평균**도 돌려준다. 안 산 칸은 기존 방식대로 평균 빌드만큼 샀다고 보되,
  **아이템이 올리는 체력은 전부 추가 체력**이므로 빈 칸 몫은 체력 몫과 같은 값을 쓴다 (새로 정한 수치 없음).
- 기준 상대를 잠깐 바꿨다 되돌리는 **모든 경로**(`atDefault`, `withNowTarget`, 상대 직접 고르기)가
  추가 체력을 함께 챙긴다 (`savedTarget()` 하나로 모음). 빠뜨리면 `setTarget` 이 나머지를 기본값으로 되돌려 버린다.
- 계산 기억(캐시) 열쇠 **여섯 곳 전부**에 들어갔다 (`targetKey()` 하나로 모음 + `scoring.js memoKey`).

## 4. 회복·흡혈·보호막의 중복 계산 점검 (요청 2)

실제로 겹쳐 세는 곳이 있는지 여섯 갈래를 모두 따라갔다.

| # | 갈래 | 어디로 들어가나 | 중복? |
|---|---|---|---|
| 1 | 아이템 효과 회복·보호막 (`effects` 11개) | `itemSelfHeal` / `itemSelfShield` → 합이 `itemSelfHp` → EHP | 아니오 (이번에 가름) |
| 2 | 규칙 `selfHeal` (원형질 안전벨트 700) | EHP 에만. **상대 회복량 추정에는 안 들어간다** | 중복 아님 — **누락** (4.2) |
| 3 | 챔피언 기술 자기 회복·보호막 | `selfHeal` / `selfShield` → EHP, 회복분만 상대 회복량에 | 아니오 (`targetShare` 로 자기 몫만) |
| 4 | 생명력 흡수·모든 피해 흡혈 | `vampHeal` → EHP + 상대 회복량 | 아니오 |
| 5 | 피바라기 | 흡혈(`LS` 0.15)로 `vampHeal`, 넘친 회복이 보호막(315)이라 `itemSelfShield` 에도 | **같은 흡혈에서 두 번 샐 수 있다** (4.3) |

### 4.2 누락: 원형질 안전벨트

규칙은 `selfHeal: 700` 을 "생명선: 체력 +300 + 회복 400 + 저항 비례 → 한타 1회 약 700" 으로 적어 뒀다.
**이 700 은 EHP 에만 들어가고 상대 회복량 추정에는 들어가지 않는다.** 즉 적이 이 아이템을 사도 치유 감소 값이 안 오른다.
고치려면 700 중 '진짜 회복'인 400 만 떼야 하는데, **원본 설명의 수치가 데이터에 비어 있다**(`체력을 0 회복`).
규칙 설명문에 적힌 300/400 은 사람이 정한 가정이지 원본 수치가 아니므로, **임의로 확정하지 않고 보류 항목으로 남겼다.**

### 4.3 피바라기: 흡혈과 보호막이 같은 뿌리

원본은 넘친 회복(생명력 흡수 초과분)을 보호막으로 준다. 지금 계산은 흡혈 전액(`vampHeal` 74)과
보호막(315)을 **각각 더한다** — 넘친 몫을 두 번 셀 수 있다. **기존 동작 그대로 뒀다** (EHP 쪽 가정이라 C1 범위 밖).
C1 뒤로는 적어도 상대 회복량 추정에서는 보호막 315 가 빠져, 이 겹침이 치유 감소 추천을 부풀리지는 않는다.

### 4.4 증강 '흡수'가 아군 지원으로 들어간다

`cv.skillVamp`(한결같은 일격)는 자기 자신을 회복시키는데, 계산은 `out.heal`(아군에게 준 회복·보호막) 통에 더한다.
그래서 ① 내 버티는 힘에 안 들어가고 ② 지원 지표를 부풀리고 ③ 상대 회복량 추정에도 안 잡힌다.
`healToDamage`(죽음의 원)가 그 값을 다시 읽으므로 같이 어긋난다. **이번에 손대지 않았다** (가중치에 영향이 가는 변경이라 별도 승인 필요).

| 란두인의 예언 | '평타 피해 감소'로 분류 | 원본은 **"치명타로 받는 피해량이 30% 감소"**. 분류를 '기본 공격 피해 감소'와 '치명타 피해 감소'로 갈랐다. 다만 **계산은 둘 다 `ehpPhysMult` 하나로 근사**하므로 서로 구분되지 않는다는 사실을 표에 적었다 |
| 물리·마법 관통 | 요약 표 '아니오 (내 능력치만)' ↔ 상세 설명 '상대 방어력과 함께 계산' | **상세가 맞다.** `mitigation(TARGET.ARMOR/MR, …)` 로 상대 저항과 함께 계산된다. 가짜 키에 설명이 비어 기본 문구로 떨어진 것 → 채웠다 |
| 능력치 ↔ 조건부 고유 효과 | 둘을 '수치 계산' 하나로 묶었다 | 요약 표를 **'조건부 고유 효과로 계산'과 '능력치로만 계산'** 두 칸으로 갈랐다 (관통 13·5개는 능력치 쪽). 이동 속도 26개는 키 이름이 능력치 그대로라 아직 고유 효과 칸에 세어진다 — 분류의 한계로 표에 적어 뒀다 |

`docs/아이템_효과_구현_연결표.md` 는 **상대 대응 효과만** 보는 표임을 머리말에 명시했다.
아이템의 **모든 고유 효과** 구현 여부는 `docs/아이템_검증표.md` 쪽이고, 원본 수치까지 전부 대조하는 일은
**Phase 5A(`tools/item_source_audit.js`, 아직 안 함)** 로 따로 잡혀 있다.

## 6. 수정안과 달라진 결정 두 가지

1. **`TARGET.SHIELD` 를 만들지 않았다.** 수정안 C1 은 보호막을 `TARGET.SHIELD` 로 따로 담되 아무 계산도 안 읽게 하자고 했다.
   읽는 데가 없는 값을 기준 상대에 넣으면 캐시 열쇠가 하나 더 늘고, 보호막 감소 수치가 생기기 전까지는 쓰이지도 않는다.
   보호막 양은 이미 `itemSelfShield` · `selfShield` 로 꺼내 볼 수 있으므로, **읽는 쪽이 생길 때 같이 넣는 편**이 맞다고 보고 뺐다.
2. **추가 체력의 완충 밴드는 '체력'의 밴드를 쓴다.** 처음에는 추가 체력 자신의 5%로 쟀는데,
   추가 체력이 300 이면 밴드(15)가 반올림 단위(50)보다 작아 **적이 아이템을 살 때마다 계산 기억이 전부 무효가 됐다
   (408번 중 408번)**. 추가 체력은 체력의 일부이고 같은 50 단위로 반올림하므로 체력 밴드(5%)로 재는 것이 맞다.

## 7. 성능 (요청 2 — Phase 3 기준 유지)

`node tools/heal_churn.js` 로 같은 5판을 다시 쟀다 (도구도 추가 체력을 보도록 고쳤다).

**추가 체력을 캐시 열쇠에 넣었는데도 재계산이 늘지 않았다** (57 → 56). 추가 체력은 체력과 같이 움직여
대부분 기존 재계산 회차에 묻힌다. 회복량이 바뀐 횟수가 33 → 29 로 준 것은 C1 로 보호막이 빠지면서
값이 덜 출렁이기 때문이다. 재계산 간격의 최솟값은 8.9초(아리 판)인데, 그 회차는 방어력·체력도 같이 움직여
**C1·C2 전에도 재계산하던 지점**이다. 따라서 **추가 최적화는 하지 않았다.**
게임 중 실제 체감 시간은 측정하지 않았다 (실제 플레이 필요 — 이 숫자는 로그 재생 결과다).

# 9. 추가 체력 갱신 조건 점검 (2026-11-25 추가)

C2 에서 추가 체력 완충 밴드를 **자기 값의 5% → 최대 체력의 5%** 로 바꿨다.
"최대 체력이 높은 상대에서 추가 체력만 크게 움직였을 때 갱신이 빠지지 않나"를 실제 기록으로 쟀다
(`tools/band_check.js`, 성능을 더 깎으려는 게 아니라 조건이 맞는지만 본다).

## 9.2 왜 그런가 — 추가 체력 조건이 사실상 작동하지 않는다

갱신 기준만 바꿔 가며 같은 408 이벤트를 다시 흘렸다.

| 갱신 기준 | 재계산 | 추가 체력이 달랐는데 넘어간 자리 (최대 차이) | 그중 1순위·Top3·다음구매·빌드가 달라지는 자리 |
|---|---|---|---|
| **지금: 최대 체력의 5%** | 57/408 | 127 (150) | **4** |
| 고정 200 | 57/408 | 127 (150) | 4 |
| 고정 100 | 67/408 | 80 (50) | 3 |
| 차이가 있으면 항상 | **86/408** | **0 (0)** | **0** |
| Phase 3 이전(추가 체력을 아예 안 봄) | 57/408 | 127 (150) | 4 |

**지금 기준은 '추가 체력을 아예 안 보는 것'과 숫자가 완전히 같다.** 추가 체력은 최대 체력의 일부라
최대 체력 밴드(약 160~210)보다 작게 움직이고, 반올림 단위가 50 이라 차이가 최대 150 에서 멈춘다.
즉 **추가 체력 조건이 재계산을 한 번도 혼자 일으키지 못한다**. 캐시 **열쇠**에 넣은 것은 여전히 맞다
(묵은 기준으로 계산한 결과를 돌려주지 않게 막는다). 틀린 것은 **기준을 언제 갱신하느냐** 쪽이다.

계산으로 본 최악(`tools/band_check.js` ②): 최대 체력 5000 이면 밴드 250 → 추가 체력 차이 **200** 까지 삼킨다.
그 200 은 거인 학살 증폭 몫의 **13.3%**(`tgtBonusHpAt` 1500 기준), 점수로 **0.042** 다.

## 9.3 제안 (승인 전, 아직 안 고침)

- **추가 체력은 차이가 있으면 바로 갱신** (밴드에서 빼기). 비용은 재계산 57 → **86회/408**(판당 약 6회 늘어남),
  Phase 3 이전(57)과 비교해도 한 판에 29 번이다. 지금 재계산 한 번이 체감되는지는 **측정 안 했다**.
- 재계산을 늘리기 싫으면 **고정 100** 이 중간값이다 (67회, 남는 차이 최대 50, 달라지는 자리 3).
- 어느 쪽이든 **갱신 조건 변경**이라 승인 뒤에 한다. 이번에는 바꾸지 않았다.
