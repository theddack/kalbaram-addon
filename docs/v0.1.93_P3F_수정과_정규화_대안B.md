## 1. 아이템 업그레이드 증강의 보유 조건

### 무엇이 문제였나

`augStatsOf()` 가 `rule.statsResolved` 를 **아이템 보유와 상관없이** 넣었다.
`rule.items` 는 태그와 '꼭 넣을 아이템(must)'에만 쓰이고 능력치에는 안 걸렸다.

| 증강 | 필요한 아이템 | 조건 없이 들어가던 것 |
|---|---|---|
| 꽃피는 새벽의 검 업그레이드 | 꽃피는 새벽의 검 | 공격 속도 +100% |
| 굶주린 히드라 업그레이드 | 굶주린 히드라 | itemStats |
| 죽음의 무도 업그레이드 | 죽음의 무도 | 효과 1개 |
| 폭풍 쇄도 업그레이드 | 폭풍 쇄도 | 효과 1개 |

그래서 그 아이템을 **꼭 들어야 하는** 몰빵 빌드가, 들지 않아도 되는 '상한' 빌드보다
증강 효과가 낮게 나왔다 (징크스 + 꽃피는 새벽의 검 업그레이드: 기본 392.2 → 몰빵 275.2 → 상한 394.9 = 역행).

### 어떻게 고쳤나

`augStatsOf(chosen, rules, champ, items)` — 지금 평가하는 아이템 목록을 받아,
필요한 아이템이 없으면 `{_effects: []}` 를 돌려준다. 빌드 탐색·아이템 순위·구매 추천·화면이
모두 자기가 보고 있는 아이템 목록을 넘긴다. 목록을 안 넘기는 계산(증강 출력 가중치, 설명 칸)은
예전 그대로다.

**한 가지 더 손봤다.** 조건을 넣고 나니 증강 **순위**에서 이 증강들이 '수치 이득 0' 이 됐다.
지금 빌드에 그 아이템이 없으니까다. 이 증강을 고른다는 건 그 아이템을 산다는 뜻이므로,
증강 순위를 잴 때는 **전설 한 칸(가장 나중에 뽑힌 칸)을 그 아이템으로 바꿔서** 잰다.

### 회귀 테스트

`tests/item_effects.test.js` — 아이템을 요구하는 수치 증강을 **데이터에서 전부 찾아** 각각
- 그 아이템이 없으면 능력치도 효과도 비어 있고
- 있으면 들어가고
- 꽃피는 새벽의 검 없이 들면 **공격 속도가 안 오르고**, 들면 크게 오르고
- 아이템 목록을 안 넘기면 예전처럼 그대로 들어간다

를 확인한다. 증강이 더 늘어도 테스트가 자동으로 같이 본다.

## 2. 라일라이의 수정홀

### 무엇이 문제였나

`control += (cv.controlPerCast || 0) * casts` 에서 `casts` 가 **꺼지지 않은 스킬 칸 수**였다.
라일라이는 "스킬로 적에게 **피해를 입히면**" 조건인데 피해 없는 스킬 칸까지 셌다.
피해 없는 스킬을 가진 챔피언이 173명 중 103명이고, 타릭은 피해 스킬이 1개인데 4개로 셌다.
결과적으로 **173명 전부 제어력 증가가 1.20 으로 같았다.**

### 어떻게 고쳤나

피해가 나는 스킬 칸(`s.dmg > 0`)만 센다.

| 값 | 챔피언 수 |
|---:|---:|
| 0.30 | 8 |
| 0.60 | 28 |
| 0.90 | 71 |
| 1.20 | 66 |

### comboTimes 일관성 검토

엔진의 다른 '스킬 사용 시' 효과는 `comboTimes()` 로 한타 창 안에서 쿨다운에 따라 횟수를 깎는다.
라일라이만 그 경로를 안 지나갔다. 다만 **깎아도 값이 같다** — 칸마다 1번씩만 세고 있어서,
쿨이 한타보다 긴 스킬도 1번이고 짧은 스킬도 1번이다. 그래서 **세는 법은 그대로 두고 근거만 규칙에 적었다.**
(아이템 효과 전체에 재사용 대기시간이 안 들어가 있는 문제는 그대로 남아 있다 — 7절)

### 결과

균형 빌드 채택: 라일라이 0명 → 0명 (기본값 기준, 바뀌지 않음), 지크의 융합 18명 → 18명.
제어력이 갈라졌을 뿐 추천은 거의 그대로다.

## 4. 정규화 대안 B

### 구현

| 실험 설정 | 뜻 |
|---|---|
| `NORM=median` | **대안 B.** 지표 분모를 전 챔피언 균형 빌드 중앙값으로 (모든 챔피언 공통) |
| `NORM=scaled` | **대안 B′.** 분모는 지금처럼 챔피언 맨몸, 지표마다 '보통 빌드 비율' 중앙값으로 한 번 더 나눔 |
| `NUMK=8.4` | 수치 세기만 따로 (아래 4-3) |

분모 표는 `tools/norm_median.js --write` 가 **지금 기본값으로 한 번 재서** 만든다.

```
중앙값     combo 1749.31 · dps 262.83 · ehp 6737.23 · support 0 · mobility 399.6 · control 1.5
분모로 쓸 값 combo 1749.31 · dps 262.83 · ehp 6737.23 · support 1139.51 · mobility 399.6 · control 1.5
```

지원은 173명 중 163명이 0이라 중앙값이 0이다. 0으로 나눌 수 없어 **0이 아닌 값들의 중앙값**(1,139.51)을 쓴다.
바닥값 600을 쓰면 지원만 척도가 작아져 서포터가 지원 아이템으로 과하게 쏠린다.

### 4-1. 순환 문제 — 수렴하지 않는다

물어보신 순환을 `--iter 3` 으로 직접 재 봤다. 대안 B 의 분모로 빌드를 다시 짜고 다시 재면:

| 회차 | combo | dps | ehp | support | control |
|---|---:|---:|---:|---:|---:|
| 1 (기본값으로 잼) | 1,749 | 263 | 6,737 | 1,140 | 1.50 |
| 2 (대안 B 로 잼) | 1,267 | 181 | 7,972 | 1,195 | 1.35 |
| 3 | 1,443 | 242 | 7,203 | 1,083 | 1.50 |
| 2→3 변화 | **+14.0%** | **+33.2%** | −9.6% | −9.3% | +11.1% |

**고정점에 모이지 않고 오르내린다.** 1회차로 얼어붙여 쓰는 수밖에 없고,
그 1회차 값은 '지금 기본값이 짠 빌드'에 달려 있다 — 즉 **대안 B 는 지금 목적함수를 기준으로 삼는다.**
이건 대안 B 자체의 성질이지 구현 문제가 아니다.

### 4-2. 173명 균형 빌드 변화

| | 대안 B | 대안 B′ |
|---|---:|---:|
| 빌드 그대로 | 60 / 173 | 64 / 173 |
| 빌드 바뀜 | **113** | 109 |
| 바뀐 칸 합계 | **270** | 220 |

역할별 바뀐 챔피언 (대안 B): 암살자 15/17 · 전사 40/50 · 메이지 26/35 · 탱커 12/24 · 서포터 11/18 · 원딜 9/29

**역할별 이상 추천 — 전사·암살자가 풀탱으로 간다.**

> 리신: 삼위일체·몰락한 왕의 검·불경한 히드라·세릴다·그림자 검 → **워모그·케이닉 루컨·해신 작쇼·정령의 형상·스테락**
> 디아나: 리치베인·라바돈·공허·폭풍 쇄도·그림자불꽃 → **케이닉 루컨·해신 작쇼·워모그·스테락·정령의 형상**
> 렝가: 삼위일체·세릴다·요우무·불경한 히드라·그림자 검 → 칠흑의 양날 도끼·맬모셔스·월식·죽음의 무도·밤의 끝자락
> 모데카이저: 폭풍 쇄도·내셔의 이빨·공허·리치베인·라바돈 → **균열 생성기·로켓 벨트·존야·밴시·모렐로** (6칸 다 바뀜)

고친 쪽도 있다.

| | 기본값 | 대안 B | 대안 B′ |
|---|---:|---:|---:|
| 전사 50명 빌드의 치명타·공속 칸 | 89 | **50** | 57 |
| 서포터 32명 빌드의 치명타·공속 칸 | 24 | 21 | 19 |

### 4-3. 가장 중요한 것 — 대안 B 는 수치를 2.1배 작게 만든다

분모가 2.6배 커지니 **수치 몫 전체가 같이 줄어든다.** 아이템 점수에서 수치 : 태그 비율:

| | 수치 평균 | 태그 평균 | 수치÷태그 |
|---|---:|---:|---:|
| 기본값 | 0.937 | 1.071 | **0.876** |
| 대안 B | 0.446 | 1.089 | **0.409** |
| 대안 B′ | 0.451 | 1.088 | 0.414 |

즉 대안 B 에는 '**척도를 고친 것**'과 '**수치를 덜 믿고 태그·공식 추천을 더 믿은 것**'이 섞여 있다.

공식 추천 일치율을 보면 이게 그대로 드러난다.

| | 핵심 담은 챔피언 | 겹치는 칸 (평균) | 서로 다른 구성 |
|---|---:|---:|---:|
| 기본값 | 77 / 108 | 4.60 / 6 | 81 |
| 대안 B | **95 / 108** | **5.39 / 6** | **97** |
| 대안 B′ | 96 / 108 | 5.30 / 6 | 98 |
| 대안 B + 수치 세기 보정 (`NUMK=8.4`) | **59 / 108** | **3.99 / 6** | **61** |

**수치 : 태그 비율을 예전과 같게 맞추면 대안 B 는 기본값보다 나빠진다.**
보정 없이 좋아 보이던 건 대부분 '수치를 덜 믿게 된' 효과였다.

### 4-4. 증강 장면 3,038개

| | 잘 따라감 | 일부 | 못 따라감 | 역행 | 아이템 무관 |
|---|---:|---:|---:|---:|---:|
| 기본값 | 742 | 475 | 1,387 | 35 | 399 |
| 대안 B | **806** | **561** | **1,149** | **42** | 480 |

역할별로는 암살자가 크게 좋아지고(못 따라감 210 → 98, 잘 따라감 28 → 87),
**메이지·서포터는 역행이 늘었다** (메이지 7 → 16, 서포터 5 → 15).

전투 가치 손실(못 따라감·역행 장면의 '상한' 빌드 기준):

| | 장면 | >10% (δ 거절) | 5~10% | 0~5% | 손실 없음 | 평균 손실 |
|---|---:|---:|---:|---:|---:|---:|
| 기본값 | 1,422 | 1,251 (88%) | 70 | 32 | 69 | 37.3% |
| 대안 B | 1,191 | 1,120 (**94%**) | 26 | 13 | 32 | 43.1% |

δ 로 설명되는 비율이 88% → 94% 로 올라가고, **'못 봤다'로 남는 장면이 171 → 71 로 준다.**
이건 대안 B 가 실제로 잘한 부분이다.

### 4-5. 아이템별 — 구원·지크·지평선의 초점

| 아이템 | 빌드 채택 | 순위 중앙값 | 비서포터 Top10 |

| 구원 | 16 → **15** | 17 → **44** | 38 → **7** |
| 지크의 융합 | 18 → **24** | 18 → 11 | 45 → **63** |

탱커 아이템이 전 역할에 퍼지는 새 쏠림이 생긴다.

바드는 서포터라 구원 1위가 맞다.
대신 대안 B 에서는 **파이크 1순위가 지크의 융합(탱커 아이템)** 이 되는 새 왜곡이 보인다.

## 5. 대안 B 가 기존보다 나은가

| 항목 | 대안 B | 판정 |
|---|---|---|
| 구원 비서포터 과대평가 | Top10 38 → 7명 | **좋아짐** |
| 지평선의 초점 과소평가 | 채택 1 → 10명 | **좋아짐** |
| 전사의 치명타 쏠림 | 89 → 50칸 | **좋아짐** |
| 증강 장면 '못 봤다' 잔여 | 171 → 71건 | **좋아짐** |
| 빌드 다양성 | 76 → 87가지 | **좋아짐** |
| 전사·암살자가 풀탱으로 | 리신·디아나·렝가·녹턴 | **나빠짐** |
| 탱커 아이템이 전 역할로 | 지크 비서포터 Top10 45 → 63 | **나빠짐** |
| 메이지·서포터 역행 | 7 → 16 · 5 → 15 | **나빠짐** |
| 공식 핵심 일치 (수치 세기 보정 후) | 77 → 59 / 108 | **나빠짐** |
| 수치 : 태그 균형 | 0.88 → 0.41 | **섞여 있음 (설계 밖 변화)** |
| 분모의 순환 | 수렴 안 함 | **풀리지 않음** |

**결론: 대안 B 를 기본값으로 올리면 안 된다.**

이유는 세 가지다.

1. **고치려던 것과 다른 것이 같이 바뀐다.** 수치 몫이 절반이 되면서
   '척도 보정'이 아니라 '수치를 덜 믿기'가 됐다. 이걸 떼어 내면(`NUMK=8.4`) 오히려 나빠진다.
2. **새 왜곡이 더 크다.** 전사·암살자가 풀탱이 되는 건 지금의 구원·지평선 문제보다 눈에 띄는 오류다.
   이유는 분명하다 — 버티는 힘은 비율 폭이 1.16으로 좁고 한타 피해는 2.61이라,
   척도를 맞추면 **기계적으로 피해가 버티는 힘보다 싸진다.** 그런데 '버티는 힘 1칸 = 한타 피해 1칸'
   이라는 건 그 자체가 검증되지 않은 가정이다. 검증 안 된 척도를 다른 검증 안 된 척도로 바꾸는 셈이다.
3. **분모가 지금 목적함수를 기준으로 삼는다.** 순환이 수렴하지 않아, 1회차 값을 얼어붙이는 선택이 임의적이다.

대안 B′(챔피언별 분모는 유지하고 척도만 맞추기)도 결과가 거의 같다 — 풀탱 쏠림이 그대로다.
**즉 쏠림의 원인은 '전 챔피언 공통 분모'가 아니라 '척도 보정' 자체다.**

### 다음에 해 볼 만한 것 (지금은 안 함)

- **지표를 줄이는 쪽**: 기동력은 모든 빌드에서 1.05~1.14 라 가중치를 줘도 상수만 더한다.
  이걸 빼는 건 척도를 지어내지 않고도 할 수 있다.
- **버티는 힘의 비율 폭이 왜 좁은지**를 먼저 보는 쪽: 지금 EHP 계산이 방어력·체력 곱 효과를
  제대로 반영하는지. 척도를 손대기 전에 계산을 보는 순서가 맞다.
- 둘 다 **먼저 재 보고 보고**, 기본값은 승인 전까지 그대로.

## 6. v0.1.93 배포 가능 여부

  회귀 영향이 작고(1순위 0 · 빌드 칸 0) 회귀 테스트가 붙어 있다.

### 배포 전에 사람이 정해야 하는 것

`python tools/release_check.py v0.1.93` 이 막고 있는 것:

```
- desktop.py APP_VERSION 0.1.92 ≠ v0.1.93

```

버전 올리기·내역·changelog 는 **릴리스 PR 하나**에 같이 넣는 것이 지금 방식이다. 아직 안 했다.

### 판단

**계산 쪽은 배포해도 되는 상태다.** 테스트 285 + 209개가 통과하고, 기준선에서 1순위와 빌드 칸이

추천의 3분의 1이 바뀐다.** 그래서 v0.1.93 은 지금 상태로 끊고, 척도 문제는 다음 판으로 미루는 쪽을 권한다.
