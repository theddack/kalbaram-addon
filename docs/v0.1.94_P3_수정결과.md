# v0.1.94 Phase 3 — 고른 증강이 지워지던 결함 수정 결과

조사 문서: [v0.1.94_P3_증강4개제한_조사.md](v0.1.94_P3_증강4개제한_조사.md)
분류: P1 긴급 (실제로 고른 증강을 화면에서 지우고 추천에 영향을 줬음)

## 1. 무엇을 고쳤나

### M1 + M2-a — 선택 화면이 또 떴다고 고른 증강을 지우지 않는다 (`web/app.js` `applyAug`)

지웠던 코드:

```js
const extra = state.chosen.length >= 4 && state.chosen.slice(0, 4).every((a) => sure.has(a.id));
if (state.chosen.length >= 4 && !extra) {
  const keep = [...state.chosen];
  for (let i = keep.length - 1; i >= 0 && keep.length >= 4; i--) if (!sure.has(keep[i].id)) keep.splice(i, 1);
  state.chosen = keep.slice(0, 3);
  full = true;
}
```

이 블록은 "선택 화면이 또 떴다 = 아직 4개를 다 고르지 않았다"는 짐작으로, 증강 칸 그림으로 확인 못 한 증강을
빼고 남은 것을 **3개로 잘랐다.** 짐작이 틀렸을 뿐 아니라, 앞쪽에 짐작이 하나라도 끼면 `slice(0, 3)` 이
**증강 칸으로 확인된 증강까지** 잘랐다.

블록 전체를 지우고 그 자리에 왜 안 지우는지를 주석으로 남겼다.

### M3 — 직접 입력·목록에서 고르기 상한을 `AUG_MAX` 와 맞춘다

| 자리 | 전 | 후 |
| --- | --- | --- |
| `renderOffers()` 선택지 이름 직접 입력 잠금 | `chosen.length >= 4` | `chosen.length >= AUG_MAX` |
| 증강 목록에서 눌러 고르기 | `chosen.length >= 4` | `chosen.length >= AUG_MAX` |

표시 문구('증강 4개 완료', '증강 4개를 다 골랐어요')는 그대로 4개 기준이다. 보통은 4개가 맞고,
그 화면에는 '다른 증강이었다면? 목록 보기' 버튼이 있어 5·6번째도 고를 수 있다.

### 함께 고친 것 — 고른 증강 칸을 실제 개수만큼 그린다 (`renderChosen`)

`[0, 1, 2, 3]` 네 칸만 그려서, 5·6번째 증강은 **화면에 아예 없었다.** 화면에 없으니 눌러서 뺄 수도 없었다.
6칸이 잘못 찼을 때 사람이 고칠 길이 막히는 자리라 같이 고쳤다.

```js
const n = Math.min(AUG_MAX, Math.max(4, state.chosen.length));
```

### 안 고친 것

- `augocr.py` 의 `MAX_AUGMENTS = 4` — 조사에서 원인이 아님이 확인됐다. 주기 읽기 간격에만 쓰이고,
  고른 직후 확인·넓혀 찾기는 `if soon or self._verify or self._recover: return 2` 가 먼저 걸린다. 그대로 둔다.
- OCR 임계값·추천 목적함수·가중치·정규화 — 손대지 않았다.

## 2. 2026-10-15 케일 사례가 재발하지 않는지

그때 막혔던 것은 **선택 화면 카드가 안 뜬 것**이고, 까닭은 가드가 아니라 상한이었다.
당시 `AUG_MAX` 는 4였고, `applyAug` 는 `if (state.chosen.length < AUG_MAX)` 일 때만 새 선택지를 받는다.
4개가 차면 선택지를 통째로 버려서 카드가 안 떴다. 2026-10-21 `3d06504` 에서 `AUG_MAX` 를 6으로 올리며
그 길은 이미 열렸고, 가드만 남아 증강을 지우고 있었다.

재현 테스트(케일, `tests/ui.test.js`)로 수정 뒤 상태를 확인했다.

| 확인한 것 | 결과 |
| --- | --- |
| 4개(확인 3 + 짐작 1)가 찬 뒤 선택 화면이 또 뜸 → 게임 화면 카드 | 3장 뜸 |
| 확인된 증강 3개 | 그대로 |
| 틀린 짐작(극악무도) | 남지만, 칸을 눌러 뺄 수 있음 |
| 선택지 이름 직접 입력 칸 | 잠기지 않음 |
| 증강 칸이 4번째를 확인해 줌 | 그대로 받음 |

이 테스트는 **수정 전 코드에서 실패**한다(확인). 즉 케일 사례는 수정 전에는 카드가 뜨는 대신 증강이 지워지는
쪽으로 흘렀고, 지금은 카드가 뜨고 증강이 남는다.

달라진 점 하나는 적어 둔다. 예전에는 틀린 짐작을 애드온이 **자동으로 지웠고**, 지금은 **남긴다.**
틀린 짐작은 ① 증강 칸이 보이면 `_settle_unverified` 가 바로잡고, ② 능력치 대조(`statCheck`)가 바로잡고,
③ 사람이 칸을 눌러 뺀다. 자동으로 지우는 쪽이 실제로 고른 증강을 날린 사례(미스 포츈 3회·그레이브즈 1회)가
기록에 있고, 틀린 짐작이 남아 손해 본 사례는 기록에 없다.

## 3. 회귀 테스트

새로 넣은 테스트 4개는 모두 **수정 전 코드에서 실패하고 수정 뒤 통과**한다.

| 테스트 | 무엇을 막나 |
| --- | --- |
| 케일: 4개가 차도 카드가 뜨고 직접 뺄 수 있다 | 카드 차단 재발 · 자동 삭제 |
| 재생(미스 포츈): 4·5·6번째가 선택 화면 뒤에도 남는다 | 405·568·860초에서 일어난 삭제 |
| 재생(그레이브즈): 확인된 증강이 앞쪽 짐작 때문에 잘리지 않는다 | `slice(0, 3)` 두 번째 결함 |
| 6칸이 다 차도 눌러 빼고 다시 고를 수 있다 | 잘못 쌓인 6칸을 사람이 못 고치는 상태 |

기존 테스트 중 두 개는 **지우던 동작을 단언하고 있어서 다시 썼다**(케일 테스트, 헤드라이너 테스트의 뒷부분).
둘 다 "확인 못 한 짐작은 뺀다" → "짐작도 남긴다"로 바뀌었다. 테스트를 통과시키려 고친 것이 아니라,
그 단언 자체가 이번에 결함으로 확인된 동작이다.

전체 결과:

| 묶음 | 결과 |
| --- | --- |
| `tests/ui.test.js` | 88 통과 (85 → 88) |
| `tests/calc.test.js` | 114 통과 |
| `tests/item_effects.test.js` | 23 통과 |
| `tests/recommend.test.js` | 14 통과 |
| `tests/baseline.test.js` | 5 통과 |
| `tests/consistency` · `link` · `log_audit` · `replay` · `scale` · `verify` | 모두 통과 |
| `tests/test_python.py` | 213 통과 |
| `tools/rec_baseline.js` | 장면 263개, 1순위·Top3·Top6·빌드·증강 등급 **바뀜 0** |
| `tools/aug_replay.py` (7판 재생) | 맞음 5 · 칸 모자람 1 · 다름 1 — Phase 2와 같음 |

재생 결과가 그대로인 것은 맞다. 재생 도구는 파이썬 추적기만 돌리고, 이번 결함은 화면(`web/app.js`) 쪽이었다.
거꾸로 보면, **파이썬 추적기는 미스 포츈의 증강 6개를 처음부터 제대로 들고 있었고** 화면만 3개로 자르고 있었다.

## 4. 수정 전후 추천 비교

실제 기록한 장면 4개(증강이 지워진 바로 그 시각, 그때의 레벨·완성 아이템)에서, 지워진 목록(수정 전)과
안 지워진 목록(수정 후)으로 '다음 구매' Top3 를 계산해 비교했다.

| 장면 | 추천에 전달된 증강 | Top3 |
| --- | --- | --- |
| 미스 포츈 550.3초 (12레벨·3칸) 전 | 3개 (부식·전부 다 무너뜨려·헤비) | 구인수의 격노검 / 무한의 대검 / 루난의 허리케인 |
| 〃 후 | 4개 (+조준경 부착) | 구인수의 격노검 / **루난의 허리케인 / 무한의 대검** |
| 미스 포츈 842.4초 (16레벨·4칸) 전 | 3개 | 루난의 허리케인 / 도미닉 경의 인사 / 구인수의 격노검 |
| 〃 후 | 4개 (+과충전) | 그대로 |
| 미스 포츈 1057.9초 (18레벨·5칸) 전 | 3개 | 루난의 허리케인 / 불경한 히드라 / 구인수의 격노검 |
| 〃 후 | 4개 (+환영 무기) | 그대로 |
| 그레이브즈 764.1초 (15레벨·3칸) 전 | 3개 | 무한의 대검 / 루난의 허리케인 / 불경한 히드라 |
| 〃 후 | 4개 (+불을 밝혀) | 그대로 |

**장면 4개 중 Top3 가 바뀐 것은 1개**, 그것도 2·3위 순서가 바뀐 정도다. 아이템 추천이 크게 흔들리고 있던 것은
아니다. 이번 수정으로 실제로 달라지는 것은 그 윗단이다.

- 고른 증강이 화면에서 사라지지 않는다 (미스 포츈은 판의 절반 이상을 6개 중 3개로 보고 있었다)
- 증강 등급·연계·몰빵 빌드가 실제 고른 증강 전부를 기준으로 계산된다
- 지워진 증강을 증강 칸이 나중에 확인해도 '바로잡기'가 아니라 '새로 더하기'로 들어오던 것이 없어진다
- 맞게 잡은 증강이 지워져 넓혀 찾기가 헛도는 CPU 낭비가 없어진다

## 5. 아직 못 한 것

- 게임 증강 칸이 실제로 몇 개까지 보여 주는지는 여전히 모른다. 이번에도 코드와 이벤트만 봤고 기록 그림은 세지 않았다.
  다만 그 답과 무관하게 이번 결함은 화면 쪽이었다.
- 그레이브즈 유형(새로고침 직후 클릭이라 이름을 못 읽음)은 못 고쳤다. Phase 2의 미확정 안내만 있다.
- 표본은 7판이다.
