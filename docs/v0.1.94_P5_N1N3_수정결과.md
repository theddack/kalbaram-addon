# v0.1.94 Phase 5 — N1·N3 적용 결과와 남은 위험

N2(상한을 넘는 선택이 오면 확인 안 된 짐작을 밀어냄)는 **보류**했다. 정상적으로 고른 증강이 지워질
회귀 위험이 있고, 기록 7판에 6칸이 틀리게 찬 판이 없다.

---

## 1. 고친 것

### N1 — 칸이 찼어도 새 선택 화면은 보여 준다 (`web/app.js` `applyAug`)

```js
if (state.chosen.length < AUG_MAX) {   // ← 이 조건을 없앴다
  const next = A.offers.map(byName);
  ...
}
```

선택 화면이 떴다는 것은 게임이 아직 더 고르게 한다는 뜻이다. 칸이 찼다면 칸 쪽이 틀린 것이다.
이제 애드온 선택지와 평가, 게임 화면 카드가 그대로 뜬다.

### N3 — 안내 문구가 고른 개수를 따라간다

| 자리 | 전 | 후 |
| --- | --- | --- |
| `renderOfferResult()` | "증강 4개를 다 골랐어요." | "증강 6개를 다 골랐어요." (고른 수) |
| `renderAugs()` 제목 | "증강 4개 완료" | "증강 6개 완료" (고른 수) |

문구만 바뀌고 동작은 그대로다. 요약 화면이 뜨는 기준은 그대로 4개다(보통은 4개가 맞고,
'다른 증강이었다면? 목록 보기' 버튼으로 계속 볼 수 있다).

## 2. 회귀 검증

## 3. 차단·삭제 조건 전수 점검 (수정 안 함)

`state.chosen.length` · `AUG_MAX` · `hudSure` · `offers` 를 쓰는 자리를 모두 봤다.

### 남은 위험

**R1. 6칸이 차면 새 증강이 안 들어간다 (4곳)** — N2를 보류했으므로 의도적으로 남긴 것이다.

| 자리 | 하는 일 |
| --- | --- |
| `applyAug` `add.length && chosen.length < AUG_MAX` | 증강 칸이 새로 확인해 준 증강을 버림 |
| `applyAug` 클릭 선택 `chosen.length < AUG_MAX` | 새로 누른 증강을 버림 |
| `renderOfferResult` '이걸로 선택' 버튼 | 못 고름 |
| `renderAugs` 목록에서 고르기 | 못 고름 |

칸이 맞게 찼다면 맞는 동작이다. 칸이 **틀리게** 찼을 때만 문제가 되고, 그때 복구는
① 증강 칸이 짝지어 알려 줌(`replaces`) ② 능력치 대조 ③ 사람이 칸을 눌러 뺌 — 세 길이다.
N1 덕분에 ③을 할 때 선택지가 눈앞에 보이므로, 빼고 바로 고를 수 있다.

**R2. 증강 목록 요약이 4개에서 뜬다** — 헤드라이너로 5·6번째를 목록에서 직접 고르려면
'다른 증강이었다면? 목록 보기'를 한 번 눌러야 한다. 게임 선택 화면을 통해 고르는 평소 흐름에는 영향이 없다.

**R3. 선택지 미리 계산이 6칸에서 꺼진다** — `warmOffers` 가 `chosen.length + 1 > AUG_MAX` 면 건너뛴다.
N1으로 선택지는 보이지만 미리 계산이 없어 첫 표시가 조금 느릴 수 있다. 계산 자체는 된다.

**R4. `hudSure` 는 올 때마다 통째로 바뀐다** — `state.hudSure = new Set(A.hudPicked || [])`.
`hudPicked` 가 빠진 이벤트가 오면 '✔ 확인됨' 표시가 '클릭으로 앎'으로 내려앉는다.
다만 실제 프로그램은 `augocr.state` 에서 `hudPicked` 를 **항상** 함께 보내므로(누적 목록),
지금 흐름에서는 일어나지 않는다. 바깥에서 `applyAug` 를 직접 부르는 경우에만 생긴다.

**R5. 선택 화면이 닫힌 것을 못 보면 카드가 남는다** — 예전부터 있던 것이고 2026-10-19 퀸 판 처리
(`offersClosed`)가 들어가 있다. N1이 바꾼 부분은 아니다.

### 위험이 아니라고 본 것

- `renderChosen` 의 칸 수 `Math.min(AUG_MAX, Math.max(4, chosen.length))` — `chosen` 이 6을 넘을 길이 없다.
  모든 추가 경로에 상한이 걸려 있고, `replaces` 경로는 빼고 넣으므로 수가 안 는다.
- N1으로 지난 선택 화면의 잔상이 뜨는 것 — `A.seq !== augSeq` 로 새 화면만 받고, 닫히면 `offersClosed` 가 지운다.
- `renderOffers` 의 직접 입력 잠금 — 6칸에서 잠기는 것은 상한대로다. 칸을 빼면 바로 열린다(테스트로 확인).

## 4. 이번 작업에서 뺀 것

- 게임 증강 칸이 실제로 몇 개까지 보여 주는지 — 지시대로 제외했다.
- N2 — 보류.
- 그레이브즈 유형(새로고침 직후 클릭이라 이름을 못 읽음) — 미확정 안내만 있다.
- 추천 계산식·OCR 임계값 — 건드리지 않았다.
