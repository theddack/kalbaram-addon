# 개발자 문서

칼바람 증강 Addon 의 데이터 수집·계산 방식과 빌드 방법. 사용법은 [사용 설명서](../사용설명서.md).

## 프로그램 (맥·윈도우)

`desktop.py` 가 화면을 독립 창(pywebview)으로 띄운다. 데이터 갱신 버튼은 프로그램에서만 보인다. ('항상 위'는 v0.1.14 에서 없앰: 켠 판에서만 전체 멈춤)
데이터는 데이터 폴더(윈도우 프로그램 폴더 안 `data\` — 쓸 수 없으면 `%APPDATA%\AramAugment`, 예전 위치는 처음 실행 때 옮김 / 맥 `~/Library/Application Support/AramAugment`)에 두고, 화면 파일은 실행할 때마다 앱 안의 것으로 덮어쓴다.

| OS | 빌드 | 결과 |
|---|---|---|
| 맥 | `./build_mac.sh` | `dist/칼바람증강Addon.app` |
| 릴리스 | `업데이트내역.md` 에 버전 내역 추가 → `python3 tools/changelog.py html` → `git tag v0.x.y && git push origin v0.x.y` | GitHub Actions 가 윈도우·맥을 빌드해 릴리스에 zip 업로드, 설명은 업데이트내역에서 |
| 윈도우 | `build_windows.bat` 더블클릭 (Python 3.12 + WebView2 필요) | `dist\칼바람증강Addon\칼바람증강Addon.exe` |

개발 중 실행: `.venv/bin/python desktop.py` (`--debug` 로 개발자 도구)

### 상점 추천 등록 (아이템 세트, `lcu.py`)

롤 클라이언트 로컬 API(LCU, lockfile 인증)로 챔피언이 정해지면 아이템 세트를 등록한다 → 게임 상점 추천 칸에 표시.
- 블록: 🎯 기본 빌드 / 🔥 "○○ 고르면" 최대 3개(첫 증강 🔥·👍 후보 중 빌드가 2개 이상 달라지는 것) / 🎲 변칙. 괄호 안 방향(원딜형·마법사형·탱커형…)은 완성 빌드 아이템으로 판정
- 게임 시작 전에 등록돼야 상점에 반영된다 → 게임 중 고른 증강은 게임 화면 오른쪽 위 '다음 구매'로 안내
- 우리 세트만 uid `kalbaram-addon-` (예전 이름 `aram-augment-tool-` 포함) 로 교체, 사용자가 만든 세트는 유지
- LCU 는 라이엇이 서드파티 공식 지원 대상이 아니라고 밝힌 API (블리츠·OP.GG 도 같은 방식으로 사용)
- **미검증**: 실제 롤 클라이언트 (가짜 클라이언트 서버로 등록 흐름·기존 세트 유지만 확인)

### Tab 점수판 적 증강 (`hudicons.BoardReader`, `augocr.py`)

**설정 '⚙ 더보기 → Tab 점수판 적 증강 읽기 (시험)'을 켰을 때만** (기본 꺼짐, 안정화 기획서: 실전 검증 전 기본 OFF). Tab 을 누르고 있으면(0.2초 뒤에도) 점수판 부분(가로 12~88% · 세로 6~90%)을 한 장 잡아 낮은 우선순위로 비교한다. 키 상태만 읽는다(P·ESC 와 같은 방식).
- 점수판 배치를 가정하지 않는다: 이번 판 챔피언 10명(적 `enemies` + 아군 `allies`, 게임 연동)의 초상화를 먼저 찾고, 적 줄만 잘라 증강 아이콘을 찾는다
- 증강마다 같은 줄에서 가장 가까운 초상화의 것으로 (한 줄에 두 팀이 나란한 배치여도 아군 것은 빠진다). 두 번 보이거나 0.95 이상이면 인정
- 그림이 같은 증강 묶음(돌진=앙파상)은 적이 무엇을 골랐는지 몰라 정하지 않는다 (`boardUnsure`)
- 읽은 것은 `aug.enemyAugs` {챔피언: [증강 id]} → 화면은 '적 증강 (점수판 시험, 대응에 안 씀)' 정보 줄로만 (대응 조언·상대 능력치엔 소환사 주문 칸 증강만)
- 간격 6초 이상, 적마다 증강 4개를 다 찾으면 그만, 자동 보호 중엔 안 읽는다. 첫 읽기는 크기를 찾느라 약 4초, 그다음 약 0.6초 (가짜 점수판 기준)
- 기록(`board`)엔 찾은 위치·점수만 남기고 점수판 그림은 남기지 않는다
- **첫 실제 판 (2026-10-19 아크샨, v0.1.48, 2520x1575)**: 6번 읽어 볼리베어 '거인의 결의' 맞음, 유나라 '기본으로 돌아가기'·소나 '민병대'는 아군(아우렐리온 솔·티모) 증강을 적으로 붙임. 증강 아이콘 자체는 그 판에 있던 것만 읽었고(크기 0.0239), **초상화 인식이 문제**: 같은 자리(가로 0.93)를 티모·녹턴·오공으로 번갈아 잡고, 아군 3명은 한 번도 못 찾음. 읽기 시간 평균 3.1초·최대 9.9초
- **미검증**: 실제 점수판 배치와 초상화 모양(둥근 테두리 등). 점수판 그림이 있어야 맞출 수 있다 (기록엔 그림을 안 남긴다)

### 게임 화면 표시 (윈도우, 창 모드·테두리 없는 창 모드)

`overlay.py`: 롤 게임 창(`League of Legends (TM) Client`) 위치에 투명 창(tkinter)을 겹쳐 그린다.
게임에 끼어들지 않고(다른 창일 뿐) 클릭은 게임으로 통과한다(WS_EX_TRANSPARENT). 게임 창이 맨 앞일 때만 보인다.
- 증강 카드 밑: 왼쪽·가운데·오른쪽 칸에 입력한 증강의 평가와 짧은 이유. 등급이 없으면 '❔ 평가 없음' (빈칸 대신)
- 상점 상자: 다음 구매·지금 살 것·조언·바꾸기. 자리는 왼쪽 위(기본)·왼쪽 가운데·오른쪽 가운데 중 고른다 (`BOX_PRESETS`, 위치 맞추기 칸). 줄 수 7·한 줄 44자 한도
- **상태별 표시** (안정화 기획서 3장, 2026-10-19 외부 테스터 제보 UX-01~06, `overlay.layout`): 증강 선택 중 → 카드 평가만 (상자·바꾸기·쿨타임 숨김) · 상점 창 열림 → 상세 · 죽어 있기만 함 → 다음 구매 + 지금 살 것 (칼바람에서 사는 때) · 그 밖(전투·시작 직후·상태 모름) → 안 띄움. 예전엔 시작 75초 동안 늘 띄웠다
- 판마다 '증강 카드' 단계별 횟수를 한 판 처리 시간 줄에: 선택지 · 3장 읽음 · 라벨 3장 · 평가 없음 (라벨 누락이 인식·계산·표시 중 어디서 생겼는지)
- 카드 이름을 2개만 읽었으면 나머지 카드 이름 자리만 2배로 키워 한 번 더 읽는다 (`reread_missing`, 2026-10-19 퀸 판 '주문 분산'). 선택 화면이 닫히면 클릭을 못 잡았어도 게임 화면 카드는 바로 지우고(애드온 창 선택지는 남김), 카드 위치를 모르면 그리지 않는다
- 위치 기본값은 위키 선택 화면 스크린샷 기준 추정(세로 70%, 카드 간격 25%). 화면의 '위치 맞추기' 슬라이더 + 미리 보기로 조정
- 전체 화면(독점) 모드에서는 보이지 않는다 → 필요하면 Overwolf 로 이전(심사)
- **미검증**: 윈도우 창 찾기·클릭 통과·화면 배율(DPI) 좌표·tkinter 스레드와 pywebview 동시 실행은 윈도우 실제 PC에서 확인 필요
- 쿨타임은 1초마다 숫자만 바뀐다 → `timers` 태그만 지우고 다시 그린다 (카드·상자·창 크기는 그대로)

### 게임 중 부담 줄이기·자동 보호 (`augocr.py`, `desktop.py`)

- numpy 계산 스레드 1개 고정(`OPENBLAS_NUM_THREADS` 등, numpy 를 부르기 전에), 글자 읽기 스레드는 조금 낮게(-1), 아이콘 비교는 가장 낮게(-2)
- 증강 칸 읽기: 고른 걸 다 찾으면 60초(`HUD_SETTLED`), 4개 다 찾으면 안 읽음 (새로 고르면 2초 뒤)
- 상점: 아래 '판매·되돌리기' 줄로 알아본 창 크기에선 위쪽 띠를 산 직후에만
- 자동 보호(`protect`): 글자 읽기 한 바퀴가 최근 20번 평균 250ms 를 넘으면 진단용 그림(상점·못 알아본 상점·증강 칸 영역)과 상점 위쪽 띠를 건너뛴다. 증강 선택 읽기·고른 증강 확인은 그대로. 평균이 절반 아래면 끈다

### 기록 (`logs/games/*/events.json`) 추가 항목

| 종류 | 내용 |
|---|---|
| `perf` | 처리 시간 요약: 이름 줄·상점·증강 칸·넓혀 찾기·화면 잡기·상점 아이템 찾기, `표시 그리기`·`표시 쿨타임만`, `추천 계산`(화면 쪽 다시 계산), `횟수`(상점 읽기/알아봄, 산 직후 읽기/알아봄 = 상점 인식 성공률, 보호 켬/끔) |
| `protect` | 자동 보호 켬/끔과 그때 평균(ms) |
| `shopfind` | (시험) 상점 그림에서 다음 구매 3개·바꿀 아이템 자리 찾기 결과. 실제 그림으로 맞춘 뒤 화면 표시를 켠다 |
| `statcheck` | 계산한 능력치 vs 게임 실제 능력치(championStats) `{level, items, augs, rows: {AD: [계산, 실제], …}}`. 레벨·아이템·증강이 바뀔 때만. 화면 능력치 표 '게임 실제' 칸과 같은 값 (5% 넘게 다르면 ⚠️) |
| `enemy.builds[].augments` | 적 소환사 주문 칸에 보이는 증강 (공식 데이터에서 상대 증강이 보이는 유일한 곳, 215개 중 9개) |

## 화면

- **증강 연계 티어 (S/A/B/C/D)**: 지금까지 고른 증강 기준으로 같은 등급 증강에 배지를 붙인다. 숫자로 평가되는 증강은 같이 골랐을 때의 빌드 가치, 나머지는 효과 종류·조건 점수로 순위 → S 상위 10% · A 20% · B 30% · C 25% · D 15%. 궁합(같이 골랐을 때 가치 − 혼자 골랐을 때 가치)이 +5 이상이면 한 단계 올리고 −5 이하면 내린다. 조건 미충족·손해는 D. 고른 증강이 챔피언 특징을 바꾸면(검을 뽑아라 → 근접) 그 기준으로 다시 판정
- **이번 선택지**: 게임에 뜬 증강 3개를 입력하면 각각의 빌드 가치(실제 숫자)·같은 등급 내 순위·몰빵 빌드와 콤보/DPS/유효 체력 변화를 비교. 칸마다 새로고침 1회 사용 여부를 체크하면, 새로고침을 안 쓴 칸 중 같은 등급 하위 40% 안에 드는 가장 낮은 칸에 '새로고침 권장' 표시
- 챔피언 선택 → 전체 증강 순위(구경용). 챔피언 스킬 특성·증강 조건·고른 증강/아이템과의 시너지 반영
- 증강 최대 4개, 아이템 6칸 직접 선택 (신발은 1개까지). 고른 아이템은 고정하고 빈 칸만 추천
- 추천 빌드 3종: 증강 몰빵 / 균형 / 변칙. 아이템마다 어떤 증강 때문에 골랐는지 표시
- 증강: 칼바람 증강 모드 목록 223개 중 비활성 8개(게임 파일 Enabled=False 7 + 위키 '현재 비활성' 1) 제외 → 215개
- 아이템 종류: 전설 107 / 신발 7 / 증강 보상 4 (22xxxx 강화템, 황금 뒤집개 — 상점 구매 불가라 자동 추천 제외, 직접 선택만 가능)
- 초기화: 증강 / 아이템 / 전체(증강 + 아이템 + 가중치 + 빌드 탭)

## 챔피언 스킬 특성

Data Dragon 챔피언 상세(패시브 + 스킬 4개 설명)에서 뽑는다.
- 특성 태그: 증강과 같은 분류기. 아군 대상 회복·보호막이 있으면 1.0, 자기 회복만 있으면 0.4
- 피해 유형 비율: 스킬 설명의 마법/물리 피해 표기 수 → 공격/마법 성향에 반반 반영
- 스킬 특징(증강 조건용): 돌진, 밀어내기, 지형 생성, 회전, 소환, 정신 집중, 은신, 이동 불가 CC, 아군 지원, 근접/원거리
  (16.20 기준 돌진 93명 · 이동 불가 CC 119 · 밀어내기 37 · 아군 지원 35 · 은신 22 · 회전 20 · 소환 14 · 정신 집중 8 · 지형 3)

## 증강 특수 규칙 (`rules.json`)

자동 분류로 못 잡는 증강 144개를 직접 정의했다 (능력치 환산 91개, 계산 기준 문장 51개). 수정 후 `python3 build_data.py` 를 다시 실행하면 반영된다.
- `tags`: 효과 태그 덮어쓰기 · `requires`: 챔피언 스킬 조건 · `items`: 연계 아이템(퀘스트·업그레이드)
- `convert`: 스탯 환산(적응형 능력치 = 공격력→주문력) · `zero`: 빌드에서 무시할 태그(유리 대포 = 체력) · `generic`: 범용
- `lift`: 빌드가 따라갈 태그 덮어쓰기. `{}`면 아이템으로 안 커지는 증강(퀸카 티아라 매혹, 눈 오는 날 눈덩이 가속) · `itemsActive`: 사용 효과 있는 완성 아이템 전체를 `items` 로 (최첨단 발명가 = 아이템 가속, 빌드할 때 설명의 `t-active` 로 채움)
- 숫자 없이 효과 종류만 있는 증강은 '증강 몰빵' 빌드에 그 효과(강도 0.6 이상, 회복·보호막 제외) 아이템을 하나는 넣는다 (`scoring.tagMust`). 메아리 시전(스킬 가속)을 고른 이즈리얼·베인이 평타 빌드 그대로 나오던 것
- 치명적 리듬: 중첩 = min(최대 10, 치명타 확률 × 초당 공격 × 유지 6초). 세 값 모두 게임 데이터(`ASPerStack`·`MaxStack`·`BuffDuration`), 가정은 '한타 중 계속 기본 공격'뿐
- 교체 추천의 판매가는 Data Dragon `gold.sell` (아이템 `sell`). 값이 없으면 실제 비용 줄을 안 보여 준다

## 공식

- 챔피언 가중치: Data Dragon 역할군(Marksman, Mage …) 프리셋 + `info.attack/magic` 비율 + `info.defense`. 화면에서 슬라이더로 조정 가능.
- 증강/아이템 효과 태그: 툴팁 마크업(`<scaleAP>`, `<healing>` …)과 한글 키워드로 분류.
- 점수식은 화면의 "공식 (가중치) 조정"과 `web/scoring.js` 상단 상수에 있다.

## 능력치 계산 (`web/stats.js`)

- 기본 능력치: 레벨 성장식 `기본 + 성장 × (L-1) × (0.7025 + 0.0175 × (L-1))`
- 레벨당 공격력: Data Dragon(16.20)이 173명 모두 0 → 위키 `dam_lvl` 로 채운다 (`champion_data.wiki_growth_fix`). 베인 판 실제 공격력과 일치
- 증강 모드 공통 능력치 (`champ.modeStats`, 위키 'ARAM: Mayhem' Global stat changes 를 `build_data.mayhem_global_stats` 가 읽음): 기본 체력 원거리 20→400·근접 20→600(레벨 비례), 공속 상한 5.0, 치명타 100% 초과 1%당 적응형 0.75. 근접 추가 방어(15)는 실측이 엇갈려(케일 3레벨: 마법 저항력만 +15) 아직 안 넣음
- 빌드 점수의 지표 기준값(`num.norm`)은 증강 없는 맨몸. 고른 증강을 기준에 넣으면 증강이 키운 지표의 아이템이 싸 보였다 (가렌 + 치명적인 공격 → 탱커 빌드)
- 아이템: 설명의 능력치 줄 22종 파싱 + 능력치를 바꾸는 고유 효과 4종(`rules.json` items: 라바돈·대천사·워모그·해신 작쇼)
- 아이템 고유 효과: CommunityDragon `items.cdtb.bin.json` 의 수치·계산식 + 문자열 테이블 설명. 모드 전용 수치는 Kiwi(칼바람 증강) → ARAM 순으로 덮어씀
- 챔피언 패시브: 챔피언 bin 의 패시브 스펠 설명(`Buff_*_Tooltip`)과 수치
- 증강: `rules.json` stats (게임 데이터 값 이름으로 연결, 91개) + 규칙 없는 증강은 설명에서 자동 추정 (아래 '새 증강 자동 반영')
- 칼바람 보정: 가하는 피해·받는 피해·회복·보호막·스킬 가속·공격 속도
- 지표: 스킬 콤보(Q·W·E·R 각 1회, 관통력 적용), 평타 DPS, 유효 체력, 회복·보호막, 기동성, 제어력
- 상대: 기본은 고정값(체력 3000·방어력 80·마법 저항력 60). 화면 '상대'에서 챔피언을 고르면 그 챔피언의 18레벨 균형 빌드 능력치로 계산
- 상대 체력 % 피해: 스킬 설명의 '(최대·현재·잃은) 체력의 N%' 피해를 상대 체력 기준으로 계산 (25명, 예: 문도 박사 Q 현재 체력 20~30%, 제이스 E 최대 체력 8~22%). 체력 소모·조건 문구는 제외
- 스킬 랭크: 궁극기 6/11/16, 기본 스킬은 Q→W→E 균등 배분으로 가정

## 숫자가 아닌 효과의 환산 (rules.json `stats` + `model`)

증강 138개(215개 중)·아이템 62개(118개 중)가 숫자로 평가된다. 환산 기준은 증강마다 `model` 문장으로 적어 두고 화면에 '📐 계산 기준'으로 보인다.

| 효과 | 환산 | 예 |
|---|---|---|
| 적중 시 쿨 감소 r초 | 스킬 가속 = 100 × 공격 속도 × r | 신비한 주먹: 공속 0.89 → 가속 +111 |
| 쿨 f% 를 확률 p 로 반환 | 가속 = 100 × (1/(1 − pf) − 1) | 대마법사 30% → +43, 노련한 저격수 80% × 원거리 40% |
| 궁극기 후 일시 버프 | 궁극기 쿨 대비 가동률로 평균 | 궁극의 각성, 방출 역장 |
| 무적·피해 감소 t초 | 그동안 받을 피해(초당 600 가정)만큼 버티는 힘 | 난공불락 2초 |
| CC | 제어력(콤보당 CC 초, 둔화 30%) | 공포 = 쿨 ÷ 20초 (최대 1.75초) |
| 이동 속도 | 기동성(평균 이동 속도), 조건부는 가동률 | 민병대 +100% × 30% |
| 골드·모루 | 위키 골드 효율로 능력치 환산 (주 공격 50%·체력 30%·저항 20%) | 후원 1750골드 → 주문력 +44·체력 +197 |
| 조건부 능력치 | 가동률 기대값 | 윤 탈 치명타 25% 영구 중첩, 공속 +30% × 50% |

새 지표: **기동성**(빌드 가중치 MS × 0.4), **제어력**(CC × 0.8). 챔피언 스킬·패시브 CC 시간은 설명의 'N초 동안 기절/속박/…'에서 뽑는다 (135명).

## 출처 기록과 자동 갱신

- 받은 파일마다 주소·받은 시각을 기록해 `data.json` 의 `sources` 로 남기고, 화면 '데이터 출처'(web/sources.html)에서 보인다

- `.github/workflows/refresh.yml`: 매일 03:00(한국) `build_data.py --refresh` → `tools/data_changed.py` 로 실제 변경(받은 시각 제외)이 있을 때만 커밋·사이트 배포
- 수집 원칙: 허용된 출처만, 하루 1번, 출처 표시. 승률 통계 사이트는 수집하지 않고 링크만

## 새 증강 자동 반영 (매일 갱신)

증강 목록·이름·설명·수치·아이콘은 게임 데이터에서 매번 새로 읽으므로 새 증강도 자동으로 들어온다. 사람이 판단하는 부분은 이렇게 나눈다.

| 단계 | 방법 | 결과 |
|---|---|---|
| 자동 추정 | `rules.json` 에 능력치 규칙이 없는 증강은 설명에서 **조건 없는** '능력치가 N(%) 증가/획득' 문장만 능력치로 읽는다 (`build_data.auto_stats`). 조건 문구(시·마다·동안·하면·중첩·퀘스트 …)나 대상 한정 수식어(궁극기·Q·눈덩이 …)가 있으면 읽지 않는다 | 화면에 🤖 자동 추정. 손으로 만든 규칙 12개와 대조해 12개 모두 일치, 잘못 읽은 것 0개 (16.20) |
| 새 증강 표시 | 이전 `data.json` 과 비교해 처음 본 패치(`firstSeen`)를 기록 | 그 패치 동안 화면에 ✨ 새 증강 |
| 설명 변경 감지 | 게임 원문(숫자 제외)의 해시(`srcHash`)가 바뀐 증강 | 확인 목록에 올림 (직접 만든 규칙이 있으면 '다시 확인') |
| 패치 노트 대조 | 패치 노트 '이전 ⇒ 이후' 숫자가 게임 데이터(설명·값 목록)에 있는지 | 없으면 확인 목록에 올림 (게임 파일 반영 전일 수 있음) |
| 확인 이슈 | 위 목록 + 규칙 수치 경고를 `web/review.md` 로 만들고, `refresh.yml` 이 GitHub 이슈(라벨 `데이터 확인`)를 만들거나 내용을 바꾼다 | 이슈를 보고 rules.json 을 고친다 |

가동률 같은 가정값은 자동으로 만들지 않는다 (잘못된 규칙이 자동으로 들어가면 정확도가 오히려 떨어진다).


## 패치 노트 대조 (`patch_check.py`)

패치 노트의 '이전 ⇒ 이후' 줄을 게임 데이터·위키 값과 맞춰 본다. 판정: `ok`(이후 값이 데이터에 있음) · `applied`(데이터가 이전 값이고 자리가 확실 → 패치 노트 값으로 계산) · `stale`(이전 값인데 자리 불확실 → 이전 값으로 계산, 확인 이슈) · `differ`(둘 다 없음) · `unknown`(숫자 없음).

| 대상 | 비교 | 임시 적용 조건 |
|---|---|---|
| 챔피언 모드 보정 (받는 피해량 등) | 위키 증강 모드 보정 표 | 위키 값 = 이전 값 |
| 챔피언 재사용 대기시간 | 위키 증강 모드 표 / 게임 데이터 | 이전 값과 랭크별로 일치, '처음~끝' 표기는 지금 값이 균등 간격일 때만 |
| 증강 수치 | 설명의 같은 항목 옆 숫자(앞 12자·뒤 30자), 없으면 설명·값 목록 | 이전 값과 같은 DataValue 가 정확히 하나 |
| 그 밖의 스킬 수치 | 스킬 설명 숫자 (계수 0.75↔75%, 'N초 동안' 합계↔매초×N, 30/40/50↔30~50 레벨 비례) | 적용 안 함 (확인만) |

`applied` 경로는 이전 값 데이터로 만든 시험으로 확인했다 (스웨인 받는 피해량, 쓰레쉬·가렌 W 재사용 대기시간, 지옥불 난사 발동 15→5초, 하체 운동의 날 40→50%).

## 근거 (`rules.json` basis, 화면 📐 근거 보기)

규칙 수치마다 출처를 붙인다 (`build_data.rule_basis`): 게임 데이터 값 이름 → 📊, 설명에 있는 숫자 → 📖, 그 외 숫자는 `basis` 가 필수 — `{"calc": 계산 방법, "assume": [{"what", "why", "noData"}]}`. basis 없는 가정값은 빌드 경고 + 확인 이슈. basis 가 있으면 설명 숫자와 우연히 같아도 📖 로 표시하지 않는다(신난다! 이동 속도 15% 가 설명의 공격 속도 15% 와 같았던 사례).
공통 가정값은 `web/stats.js` `ASSUMPTIONS` 한 곳에 두고 데이터 출처 페이지가 그대로 그린다.

## 기준 상대 (`tools/target_median.js`)

전 챔피언의 18레벨 균형 빌드 능력치 중앙값. 빌드 탐색 자체가 기준 상대를 쓰므로 값을 넣고 다시 돌려 안정될 때까지 반복한다 (16.20: 2511/112/63 → 2470/113/63 에서 안정. 2026-10-16 레벨당 공격력·모드 체력을 넣은 뒤 3042/112/63 에서 안정. 2026-10-18 라이엇 공식 추천 가산점을 넣은 뒤 3073/113/63 에서 한 번에 안정. 2026-10-19 크라켄 학살자 계산을 고치고 비슷한 챔피언 추천을 넣은 뒤 3148/113/63 에서 안정). 패치 후 `node tools/target_median.js` 로 다시 계산해 `stats.js` TARGET·ASSUMPTIONS 에 반영.

## 지금 골드로 살 것

`data.json` `parts`: 완성 아이템의 하위 부품 전체(이름·가격·부품). 게임 중 데이터의 `currentGold` 와 가방 속 아이템(부품 포함)으로 1순위 아이템의 남은 금액(가진 부품 가격 제외, 조합 비용 포함)과 지금 살 수 있는 가장 비싼 부품을 고른다 (`app.js` `buyNow`). 골드만 바뀌면 순위는 다시 계산하지 않고 이 줄만 갱신한다. 부품마다 `stats`(아이템 설명의 능력치 줄)도 있어서, 게임 중 지금 능력치 표·계산 vs 실제 비교(`statCheck`)에는 가방 속 부품을 더한다 (`partItems`). 빌드 추천·점수는 완성 아이템만 본다.

## 실측 (경기 결과)

`LcuWatcher` 가 롤 클라이언트 단계가 `EndOfGame`(·`PreEndOfGame`·`WaitingForStats`)이 되면 `/lol-end-of-game/v1/eog-stats-block` 을 한 번 읽어 `measure/eog_<gameId>.json` 에 저장한다 (`redact_eog` 로 이름·puuid 제거, 최근 100판). `measure_summary` 가 분당 평균을 내고 데이터 출처 페이지가 보여 준다. 클라이언트 내부 API 라 칸 이름(`TOTAL_DAMAGE_TAKEN` 등)은 커뮤니티 문서 기준이며 실제 윈도우 클라이언트에서 확인이 필요하다. 가정값(받는 피해 초당 600 등)과는 정의가 달라서(한타 중 vs 게임 평균) 자동으로 바꾸지 않는다.

### 전적 (10명 증강 정답, `lcu.Lcu.match`)

경기 결과(eog)를 받은 판은 게임이 끝난 뒤 전적 상세(`/lol-match-history/v1/games/<gameId>`)가 올라올 때까지 기다린다 (최대 10분, 게임 중엔 안 읽음).
- `lcu.redact_match`: 이름·계정 칸(`participantIdentities`)을 버리고 10명의 챔피언(숫자 key)·증강 번호(`playerAugment1~6`)·아이템·승패·피해량만. 내 칸은 puuid 로 찾아 `me=True` 만 남긴다
- 기록이 켜져 있으면 `measure/match_<gameId>.json`. 꺼져 있어도 점수판 대조 한 줄은 diag.log 에: "점수판 적 증강 대조: 맞음 · 틀림 · 못 읽음 / 적 증강 N개" (`board_check`, 적 팀만)
- 증강 번호를 모르면(받은 데이터가 늦음) 클라이언트 번호표(`/lol-game-data/assets/v1/cherry-augments.json`, 설치된 버전 그대로)로 찾는다. 2026-10-18: 215개 번호가 데이터와 모두 일치
- 개발 도구: `python tools/match_review.py [판 수]` 가 내 최근 칼바람 증강 모드 판을 `.cache/matches/` 에 받고, `node tools/match_check.js` 가 실제로 고른 증강의 우리 등급·승패·아이템 겹침을 본다
